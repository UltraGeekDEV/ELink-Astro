Firewall node

A policy layer that joins two networks and decides which events and calls may cross, and in which direction.

A FirewallNode (FirewallNode.cs) is two full TypeSafeEVentNodes, side I and side O, joined by a FilterLink (FilterLink.cs). Each side has its own transports and connects to its own network exactly like any other node, so both networks keep running their own merges, type agreement and links. What crosses the firewall is decided by a FirewallPolicy (FirewallPolicy.cs).

The link is a pair of IEVentClient endpoints, one accepted by each node, so the two nodes run the normal link protocol over it (handshake, interest, calls, answers). The filter sits in Send and hands each package on, rewrites it, or refuses it. Packages cross as they are: nothing is deserialized except the small payloads listed under Types across the firewall.

Building one

var policy = new FirewallPolicy(
    iToO: DirectionRule.Whitelist("Temperature", "Humidity"),   // what side I may send to side O
    oToI: DirectionRule.Blacklist("Debug"));                    // what side O may send to side I

var fw = new FirewallNode("Gate", policy,
    new TCPServer(IPAddress.Any, 5700, "GateInside"),           // side I: its own transports
    new TCPServer(IPAddress.Any, 5701, "GateOutside"));         // side O

// Each side joins its own network like any node:
fw.SideI.TryEstablishConnection(insideNetworkInfo);
fw.SideO.TryEstablishConnection(outsideNetworkInfo);

fw.OnBlocked(b => Console.WriteLine($"blocked {b.Type} '{b.EventID}' going {b.Direction}"));

The two constructor arguments after the policy are the transports of side I and side O (a single ICommsProtocol or an array for each). The sides are public (SideI, SideO), so they can also be dialed by others, or used directly like any typed node; an event that side I hooks itself is an ordinary subscriber of that network.

The policy

A policy has one DirectionRule per direction, IToO (packages that travel from side I to side O) and OToI. A rule is two sets of event IDs, Allow and Deny. An ID passes if it is not denied and it is allowed; nothing passes that isn't allowed. The wildcard * stands for every ID, and an entry ending in .* (Minecraft.*) for every ID under that prefix.

IDs are compared exactly (case sensitive). The same rule governs an event, a function call and its interest, because they all route by ID. A policy is immutable and fixed when the firewall is built: to change it, stop the firewall (Stop) and build a new one.

IDs the rules never govern

The IDs the type agreement and merges use for themselves are not application events, so * does not reach them and listing them has no effect. The descriptor functions (TryInitiateNOTESDescriptor, FinalizeNOTESDescriptor, AbortNOTESDescriptor, QueryDescriptors, NOTESQueryDescriptorSet, NOTESShareDescriptors) cross for exactly the events that may cross in either direction, judged by their payload. The merge control functions (NOTESMergePing, StopEvents, AllowEvents, AwaitReady, HandleEvent) cross only with FirewallPolicy.PassMergeControl (default off). See NOTES events reference.

What crosses

For every package one node hands to the link, the filter decides by package type. "Direction" is the way the package travels.

PackageRule
Data, and an application's own ServerAdminEventCrosses if the direction's rule allows the ID.
FunctionCall (typed events are calls, and so are functions)Crosses if the direction's rule allows the ID. Otherwise the caller is answered at once with an empty return, as a provider with nothing to say would; the call is never left waiting for its timeout.
FunctionReturnAlways crosses, so a permitted call always gets its answers (a typed FireEvent completes when the acknowledgements arrive). Descriptor answers are trimmed to the events that may cross.
EventAdded, EventRemoved, ListEventsInterest. Crosses only for IDs whose data may travel the other way (see below). ListEvents is rewritten to the passable IDs and is always forwarded, even empty, because it is what tells the other node the link is up.
InterconnectRunning, QueryEvents, LinkFaultCross: they only concern this link.
CreateInterconnect, DisconnectInterconnect, Invalid, BroadcastHandshakeNever cross.

Interest: blocked events are invisible

EVent routes by interest (Links & interest routing). A subscriber on side O announces interest in X; the data would travel from side I to side O, so the announcement crosses only if IToO allows X. If it doesn't, side I never learns that anyone wants X: a publisher there sees no subscribers, FireEvent returns true without sending anything, and CallFunction returns no answers immediately. There is nothing to probe, and nothing to leak.

Prefix routes

A namespace announces itself as one prefix route (kitchen.*) rather than one ID per endpoint. Such an announcement crosses if something under the prefix may cross: the rule allows everything, or a pattern covering it, or any entry under it, and no deny pattern covers it as a whole. Each ID that then travels along the route is still judged on its own, so Allow = {kitchen.*}, Deny = {kitchen.Secret} lets the namespace be reached and answers a call for kitchen.Secret at once with nothing (harness F15).

Types across the firewall

A typed publisher needs an agreed type for the event before it can fire (see Type agreement protocol). So the firewall lets the descriptor functions cross, for the events that may cross in either direction, and looks inside their payloads: a call about one event is dropped unless that event may cross; calls carrying a list (NOTESQueryDescriptorSet, NOTESShareDescriptors) are trimmed to the events that may cross and dropped if none is left; the descriptors in answers are trimmed the same way, so a peer can't slip descriptors for other events into a network through an answer. The result:

  • A permitted event has one type across the firewall. A node on side O that hooks it with a different type is refused (HookEvent returns false), and a node that joins later learns the type when its link comes up (harness F07, F09).
  • A blocked event's type stays private to each side: the two networks may use the same ID for different types (F08).

Merges, loops and merge control

Merging a network into a firewall side works as for any node: the node that dials SideI or SideO runs TryEstablishConnection, and a later joiner takes part at once (F10). Two things are different from a plain link.

  • Merge groups. With PassMergeControl off (default), the merge pings and the freeze (StopEvents/AllowEvents) stop at the firewall: a merge on one side neither sees nor freezes the other side. That is the safe setting for a real boundary. With it on, both sides behave as one group for merges, so a loop that closes through the firewall is detected, at the price that the far side can freeze this one (F11).
  • Loops. A loop that closes through two firewalls (or a firewall and a plain link) is not detected while merge control is blocked, and an event allowed both ways would circulate. Join two networks through one firewall, or make the policies incompatible (an event allowed in only one direction can't circle).

Faults and stopping

If the link between the two sides closes without Stop (for example a side dropped it after a malformed package), the firewall passes nothing more and OnLinkLost is raised. Stop (or Dispose) stops both sides and the link; it does not raise OnLinkLost, and calling it again does nothing. Each side's own links behave as for any node (OnLinkFault on SideI/SideO). (F14)

API

FirewallNode

public FirewallNode(string nodeID, FirewallPolicy policy, ICommsProtocol sideI, ICommsProtocol sideO)

Also (string, FirewallPolicy, ICommsProtocol[] sideI, ICommsProtocol[] sideO). Creates both typed nodes (named nodeID + ".I" and nodeID + ".O") and the link. Like TypeSafeEVentNode, the constructors block briefly until each node is ready.

public TypeSafeEVentNode SideI { get; } public TypeSafeEVentNode SideO { get; }

The two nodes. Connect each to its own network with TryEstablishConnection, or let others dial it.

public FirewallPolicy Policy { get; }

The policy the firewall was built with. It never changes; to use another, build a new firewall.

public long ForwardedCount { get; } public long BlockedCount { get; }

Packages let through (the nodes' own protocol traffic on the link included), and packages, calls and malformed interest announcements kept from crossing. An interest announcement that is merely not passed is not counted as blocked.

public void OnBlocked(Action<BlockedPackage> handler)

Raised for each blocked package or call, with the direction, the event ID and the package type. Handlers run on the thread pool, never on a node's thread.

public void OnLinkLost(Action handler)

Raised when the link between the sides closes without Stop.

public void Stop() public void Dispose()

Stops both sides and the link. Idempotent.

FirewallPolicy, DirectionRule, BlockedPackage

public FirewallPolicy(DirectionRule iToO, DirectionRule oToI, bool passMergeControl = false)

Immutable. BlockAll and AllowAll are ready-made policies; Rule(FirewallDirection) reads one direction. PassMergeControl: see Merges, loops and merge control.

public DirectionRule(IEnumerable<string>? allow = null, IEnumerable<string>? deny = null)

Factories Block, AllowAll, Whitelist(params string[]) and Blacklist(params string[]); Allows(string eventID) evaluates one ID; Allow/Deny expose the sets; DirectionRule.Wildcard is "*".

public readonly record struct BlockedPackage(FirewallDirection Direction, string EventID, PackageType Type)

FirewallDirection is IToO or OToI.

Limits

  • The policy judges IDs, not payloads: it can't allow an event for some values only.
  • Answers to a permitted call are not filtered (except descriptor answers). What a provider answers goes back to the caller.
  • One firewall is one pair of sides. To restrict several networks, chain firewalls in a tree (see loops above).
  • The policy is fixed at construction. Changing it means stopping the firewall and building a new one, which drops the links of both sides.
