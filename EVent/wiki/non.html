NON dynamic objects

Use any NOTES event or function without writing a C# class for it: read, build, send and even define types at run time.

NON (NOTES Object Notation) is the name for NOTES' wire format and its type descriptions: the canonical signature, the byte layout it defines, and the JSON that describes it. A NON signature says everything needed to read and write a value (records are their fields in name order, lists are a count and the elements, optionals a presence byte and the value), so a schema compiled from it handles any agreed event with no C# type at all. The bytes are exactly those of the typed API, so dynamic and typed nodes exchange the same events in both directions. The code is in EVent/NON/ and TypeSafeEVentNode.NON.cs.

Quick tour

// Use an event someone else defined: no DTO.
var ep = await node.GetEndpointAsync("House.Setpoint");        // the agreed type, fetched from the network
var spot = ep.NewInputObject();                                  // a Spot, with zero values
spot["Floor"] = 2;
spot["Room"] = "attic";
var answers = await node.CallFunctionDynamicAsync("House.Setpoint", spot);
float target = answers[0]["Celsius"].AsFloat;
string room = answers[0]["Where"]["Room"].AsString;

// Subscribe and publish.
await node.HookEventDynamicAsync("Reading", v => Console.WriteLine(v["Celsius"].AsFloat));
var reading = (await node.GetEndpointAsync("Reading"))!.NewInputObject();
reading["Celsius"] = 20.5f;
reading.Object("Where")["Room"] = "den";                         // creates the optional record
await node.FireEventDynamicAsync("Reading", reading);

// Define a brand-new event type at run time; C# nodes may join it with a matching class.
var order = NONType.Record("Order")
    .Field("Item", NONType.String, f => f.Description("what was ordered"))
    .Field("Qty", NONType.Int32, f => f.Description("how many").Range(1, 99))
    .Optional("Note", NONType.String, f => f.Default("none"))
    .Build();
await node.HookEventDynamicAsync("Orders", v => Handle(v), define: order, description: "orders placed at the counter");

Types: NONType and NONSchema

A NONType is a leaf (one of the 15 built-in ones in NONType.Primitives: Void, bool, int8 … UInt64, float, double, decimal, char16, string; or an application's own leaf), a record (named, fields in canonical order, each field required or optional, with its documentation), or a list of a type with an optional cap. A NONSchema is a root type compiled for the wire: its signature, its documentation, and the reader and writer.

Where the type comes fromCall
An agreed event or functionnode.GetEndpointAsync(id) → NONEndpoint with Input and Returns schemas
A NON signature (a descriptor's Expected / Returns)NONSchema.FromSignature(signature, annotations) (cached)
A C# NOTES classNONSchema.For<Thermo>(); its own leaf types are registered on the way
A type description in JSON (discovery's shape)NONSchema.FromJson(json): what $Describe or schema.ToJson() prints reads back
CodeNONType.Record("Name").Field(...).Optional(...).Build(), then NONSchema.FromType(type)

The builder takes fields in any order and puts them in canonical order. NONType.ListOf(t, cap) makes a list; NONType.Self refers to the record being defined, for a type that contains itself through an optional field or a list (Record("TreeNode").Field("Value", NONType.Int32).Field("Children", NONType.ListOf(NONType.Self)) is exactly the C# TreeNode). Each field can be documented like a C# field (Documenting fields): .Description, .Range, .Default. The builder refuses what NOTES refuses: a record without fields, a duplicate field, a reserved character in a name, a record that contains itself through a required field, two different records with one name, a range on a record, a default of the wrong type (harness D02).

An application's own leaf types can't be read without their C# class (NON can't know how many bytes they take), so they must be registered, NONLeaves.Register<Stamp>(); NONSchema.For does it for the leaves of the type it is given. A signature with an unknown leaf is refused with NOTESTypeException.

Values: NONObject, NONList, NONValue

TypeWhat it is
NONValueA small struct: a number (stored inline, never boxed), a string, a record, a list, a leaf, or Null (an absent optional; also default). Converts implicitly from int, ulong, float, string, records and lists; AsInt32, AsUInt64, AsFloat, AsString, AsObject, AsList, AsLeaf read it back. value["Where"]["Floor"] reads through records.
NONObjectA record: its type and a flat slot array in canonical order. obj["Celsius"] by name, or obj[slot] with int slot = obj.Type.Slot("Celsius") resolved once. Has, Clear, Object(name) and List(name) (they create an absent optional record or list), Clone() (deep), ToJson(), FromJson, AsDynamic().
NONListA list of one element type, IList<NONValue>; AddObject() appends a new record, Object(i) returns one to change.

Setting a field checks the value against the field's type. Numbers convert where it makes sense: an integer into any integer field it fits (300 into a uint8 field is refused), any number into float and double (rounded, so C#'s 18.3 literal fits a float field) and into decimal (if in range), a one-character string into char16; never a fraction into an integer, never a number into bool; a record or a list must be of the same NON type (same structure, compared by signature); Null goes only into an optional field; a list refuses elements past its cap. A mismatch is a NONTypeMismatchException naming the field. A new record has its required fields at zero values (0, "", an empty list, a new nested record) and its optional fields absent.

Setting through a chain

NONValue is a struct, so C# can't assign into one returned by an indexer: obj["Where"]["Floor"] = 2 doesn't compile. Use obj.Object("Where")["Floor"] = 2 and list.Object(0)["Name"] = "Tom", or AsDynamic(). Reading through a chain works.

dynamic d = schema.NewObject().AsDynamic();   // for scripts
d.Celsius = 18.5;
d.Where = spotSchema.NewObject();
d.Where.Floor = 2;
float c = d.Celsius;

JSON. ToJson() writes numbers as numbers, strings as strings, records as objects of their fields (absent optional fields as null), lists as arrays, the shape field defaults use. NONObject.FromJson(type, json) and schema.ReadJson(json) read it strictly: a missing required field, a field the type doesn't have, or a value of the wrong kind is a FormatException with its path (D03).

Defaults. An optional field that arrives absent reads as its default, taken from the agreed documentation: a dynamic reader always uses the defaults the network agreed on.

On the network

The dynamic calls sit next to the typed ones on TypeSafeEVentNode and use the same agreement, routing, gate and timeouts; each has a blocking form without Async.

Task<NONEndpoint?> GetEndpointAsync(string eventID)

The agreed type as schemas (fetched and adopted if this node doesn't know it yet), with IsEvent, Description, NewInput(), NewInputObject(), NewAnswerObject(). Null if no type is agreed anywhere, or it uses a leaf this node can't read.

Task<bool> HookEventDynamicAsync(string eventID, Action<NONValue> callback, NONType? define = null, string? description = null)

Also with Func<NONValue, Task>. Subscribes with the agreed type. If none is agreed, define is proposed as the event's type, like a typed HookEvent proposes its class; without it the call returns false. false too if define differs from what the network agreed, or the ID is a function. UnhookEventDynamic(id, callback) removes it.

Task<bool> FireEventDynamicAsync(string eventID, NONValue value, TimeSpan? timeout = null, CancellationToken cancellationToken = default)

Like FireEventAsync: true once every subscriber has handled it (including nobody being interested); false if the ID has no agreed type, is a function, or the value isn't of the agreed type.

Task<bool> RegisterFunctionDynamicAsync(string eventID, Func<NONValue, NONValue> handler, NONType? defineInput = null, NONType? defineOutput = null, string? description = null)

Also with Func<NONValue, Task<NONValue>>. Provides a function; the handler's Null means no answer. Define both types to propose them when none is agreed. UnregisterFunctionDynamic(id, handler) removes it.

Task<List<NONValue>?> CallFunctionDynamicAsync(string eventID, NONValue input, TimeSpan? timeout = null, CancellationToken cancellationToken = default)

Like CallFunctionAsync: every provider's answer as a value of the agreed return type; empty if nobody provides it; null if there is no agreed type, the ID is an event, or the input isn't of the agreed input type.

The harness checks both directions: a dynamic publisher reaches a typed subscriber and the other way round (D04); dynamic and typed callers and providers answer each other, and a wrong input type is refused before anything is sent (D05); a type defined dynamically becomes the network's type, a C# class with the same shape joins it and one with another shape is refused, and its documentation shows in discovery (D06); a function inside a namespace is called dynamically, with its type from GetEndpointAsync or read from the directory's JSON (D07).

Cost

A schema is compiled once per signature (cached), fields are slots in an array, numbers are stored inline, and the writer goes straight into a pooled buffer. Harness D08 measures a documented Thermo (31 bytes) against the typed serializer; see the result. Reading and writing cost about the same as the typed API; name lookups cost a dictionary lookup, which resolving a slot once avoids.

Limits

  • An application's own leaf types need their C# class (registered with NONLeaves).
  • The dynamic wrapper is for convenience; the indexers are faster.
  • Ranges are documentation: they are not checked on set or on send.
  • A dynamic definition proposes a type only when the ID has none; it never changes an agreed type.
