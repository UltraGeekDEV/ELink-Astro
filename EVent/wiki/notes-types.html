Defining NOTES types

Writing IBinaryConvertible types that NOTES can describe: records, collections and recursive types.

The IBinaryConvertible contract

IBinaryConvertable.cs
public abstract class IBinaryConvertible            // abstract class, despite the "I"
{
    public abstract string Name { get; }            // type name; part of every NOTES signature
    public abstract NOTESDescriptor Descriptor { get; }
    public abstract bool FromBytes(ref Span<byte> data);  // consume from the front, advance the span
    public abstract byte[] ToBytes();
}

All generic APIs also require a public parameterless constructor (where T : IBinaryConvertible, new()). Receivers create an instance and fill it in.

A composite type, step by step

This is CatDescriptor from the Examples, annotated:

Examples/TestClass.cs (annotated)
using Event.Connections.Models.BaseBinaryConvertibles;   // NOTESDescriptor
using EVent.Connections.Models.BaseBinaryConvertibles;   // IBinaryConvertible, primitives

public class CatDescriptor : IBinaryConvertible
{
    // 1. Members are themselves IBinaryConvertible, and must never be null
    public BinaryConvertibleString CatName { get; set; } = new BinaryConvertibleString();
    public BinaryConvertibleUInt64 ID      { get; set; } = new BinaryConvertibleUInt64();
    public BinaryConvertibleUInt64 Age     { get; set; } = new BinaryConvertibleUInt64();
    public BinaryConvertibleString Owner   { get; set; } = new BinaryConvertibleString();

    // 2. Name: the root of the signature ("Cat.Name:string", ...)
    public override string Name => "Cat";

    // 3. One static descriptor per type
    private static readonly NOTESDescriptor descriptor = new NOTESDescriptor();
    public override NOTESDescriptor Descriptor => descriptor;

    // 4. Register every member once, in the static constructor.
    //    The string is the field's NOTES name. It need not match the C# property name.
    static CatDescriptor()
    {
        descriptor.RegisterField("Name",  (CatDescriptor x) => x.CatName);
        descriptor.RegisterField("ID",    (CatDescriptor x) => x.ID);
        descriptor.RegisterField("Age",   (CatDescriptor x) => x.Age);
        descriptor.RegisterField("Owner", (CatDescriptor x) => x.Owner);
    }

    public CatDescriptor() { }                      // 5. required by new() constraints
    public CatDescriptor(BinaryConvertibleString name, BinaryConvertibleUInt64 id,
                         BinaryConvertibleUInt64 age, BinaryConvertibleString owner)
    { CatName = name; ID = id; Age = age; Owner = owner; }

    // 6. Delegate (de)serialization to the descriptor
    public override bool FromBytes(ref Span<byte> data) => descriptor.FromBytes(this, ref data);
    public override byte[] ToBytes() => descriptor.ToBytes(this).ToArray();

    // optional: JSON-like dump of the current values
    public override string ToString() => descriptor.ToString(this);
}

Rules

  • Register in the static constructor. RegisterField instantiates the field type (new TField()), which triggers that type's own static constructor, so nested descriptors are complete in time.
  • The accessor must return the live member instance. Deserialization fills that instance in place (fieldProvider(target).FromBytes(...)), so never return a copy.
  • Initialise every member to a non-null instance, both in the default constructor and in property initialisers.
  • Register each member exactly once. A type with a duplicate registration name is refused (NOTESTypeException, logged; HookEvent and FireEvent return false).
  • Type names and registration names must be non-empty and must not contain any of {}[]:,=<>|?@. They're the signature's delimiters, or reserved for later extensions (Signature grammar).
  • Pick a stable Name. Changing it changes the signature of every event that uses the type anywhere (I-33).

Leaves and children

RegisterField NOTESDescriptor.cs looks at the member type:

Nesting works to any depth. NOTESTEstObject in the Examples has three leaves and two NOTESTestChild children, each with one leaf. Its signature is the three entries shown in the diagram on What is NOTES?.

Caution

A composite type that forgets to register its members has an empty descriptor, so it's silently treated as a leaf and its own ToBytes is used. Plain (untyped) serialization writes all leaves before all children, whatever order they were registered in (I-32).

Leaf types as event types

A leaf type can be an event's type directly, for example HookEvent("temp", (BinaryConvertibleFloat t) => ...) or a NOTESVoid “signal” event. The type is then its own single field: the signature is ["=float"] or ["=Void"], and the payload is exactly the leaf's own bytes.

Tip

The implicit conversions let you write new CatDescriptor("Tom", 1, 3, "Attila"). Generic type inference doesn't apply user-defined conversions, though, so FireEvent("X", 21.5f) won't compile. Write FireEvent("X", (BinaryConvertibleFloat)21.5f) or give the type argument explicitly.

Writing a custom leaf type

For a value that isn't a composition of existing types, implement the bytes yourself and leave the descriptor empty:

Custom leaf (illustrative)
public class BinaryConvertibleBool : IBinaryConvertible
{
    private static readonly NOTESDescriptor descriptor = new NOTESDescriptor(); // empty => leaf
    public override NOTESDescriptor Descriptor => descriptor;
    public override string Name => "bool";          // appears in every signature using it
    public bool Value { get; set; }

    public override bool FromBytes(ref Span<byte> data)
    {
        if (data.Length < 1) return false;             // validate, don't throw
        Value = data[0] != 0;
        data = data.Slice(1);                          // ALWAYS advance past what you read
        return true;
    }
    public override byte[] ToBytes() => new[] { (byte)(Value ? 1 : 0) };
    public static implicit operator BinaryConvertibleBool(bool v) => new() { Value = v };
}

A leaf must be self-delimiting: FromBytes has to consume exactly its own bytes, because the next field starts where it stops. Variable-length leaves need a length prefix, like BinaryConvertibleString. TCPConnectionData breaks this rule and can't be embedded in other types: it consumes the rest of the buffer.

Collections

BinaryConvertibleCollection<T> is a NOTES-native type (commit 729bbe2). Its element type is part of the signature and its elements are written in NOTES layout, so every rule that applies to a field applies inside a collection too: a reordered element type still lines up, and a different or superset element type is refused. Collections are ordered and homogeneous (one element type).

public class Kennel : IBinaryConvertible
{
    public BinaryConvertibleString Street { get; set; } = "";
    public BinaryConvertibleCollection<Cat> Cats { get; set; } = new();
    public override string Name => "Kennel";
    private static readonly NOTESDescriptor d = new();
    public override NOTESDescriptor Descriptor => d;
    static Kennel()
    {
        d.RegisterField("Street", (Kennel x) => x.Street);
        d.RegisterField("Cats",   (Kennel x) => x.Cats);                    // Cat[]      (uncapped)
        // d.RegisterField("Cats", (Kennel x) => x.Cats, maxCount: 16);     // Cat[<=16]  (capped)
    }
    public override bool FromBytes(ref Span<byte> data) => d.FromBytes(this, ref data);
    public override byte[] ToBytes() => d.ToBytes(this).ToArray();
}

// Signature:  =Kennel
//             Cat{Age:UInt64,ID:UInt64,Name:string,Owner:string}
//             Kennel{Cats:Cat[],Street:string}
var k = new Kennel { Street = "Main", Cats = new List<Cat> { new("Tom", 7, 3, "Ann") } };
typed.FireEvent("kennel", k);
TopicBehaviour
Element typesAny NOTES type: leaves (string[]), records (Cat[]), and collections (int32[][]).
Using itIt's an IList<T> (and IReadOnlyList<T>), so it works exactly like a List<T>: indexer, Add, AddRange, Insert, Remove, Count, foreach, LINQ and collection initializers (new CatList { tom, felix }). Implicit conversions from List<T>, HashSet<T> and arrays still work for the plain collection.
CapsOptional, uncapped by default. A cap is declared on a collection definition or where a collection field is registered, never inside a message. It's part of the type, so capped and uncapped (or two different caps) don't match, and it's enforced on both sides: FireEvent returns false for too many elements, and a receiver drops a message whose count exceeds the cap. See Caps below.
Collection-typed eventsHookEvent("names", (BinaryConvertibleCollection<BinaryConvertibleString> n) => ...) gives ["=string[]"]. Hooking a capped definition instead, such as a NameList capped at 16, gives ["=string[<=16]"].
NullsElements can't be null: FireEvent returns false. A whole collection field can be absent if it's registered as optional (Cats:Cat[<=4]?).
Wireint32 little-endian count, then each element in NOTES layout, with no per-element length prefix. Every element must encode to at least one byte (a collection of zero-byte values is refused), which is what bounds a receiver's work by the message size.
Outside NOTESThe collection's own ToBytes, used by the core and by raw events, is unchanged: a count, then length-prefixed items (Wire format).

Caps

A cap is one number, “at most N elements”, and it belongs to a collection. There are two places to declare it (commit eca89fb):

// 1. A collection definition: a class whose own descriptor holds the cap. Reuse it anywhere.
public class CatList : BinaryConvertibleCollection<Cat>                  // Cat[<=16]
{
    private static readonly NOTESDescriptor d = NOTESDescriptor.Collection(maxCount: 16);
    public override NOTESDescriptor Descriptor => d;
}

//    Nested collections: each definition caps only its own level.
public class Row : BinaryConvertibleCollection<BinaryConvertibleInt32>   // int32[<=4]
{
    private static readonly NOTESDescriptor d = NOTESDescriptor.Collection(maxCount: 4);
    public override NOTESDescriptor Descriptor => d;
}
public class RowList : BinaryConvertibleCollection<Row>                  // int32[<=4][<=2]
{
    private static readonly NOTESDescriptor d = NOTESDescriptor.Collection(maxCount: 2);
    public override NOTESDescriptor Descriptor => d;
}

public CatList Cats { get; set; } = new();
d.RegisterField("Cats", (Kennel x) => x.Cats);                           // Cats:Cat[<=16]
typed.HookEvent("cats", (CatList c) => ...);                              // =Cat[<=16]

// 2. On a collection field, where it's registered.
public BinaryConvertibleCollection<Cat> Pets { get; set; } = new();
d.RegisterField("Pets", (Owner x) => x.Pets, maxCount: 8);               // Pets:Cat[<=8]
d.RegisterField("Age",  (Cat x) => x.Age, maxCount: 8);                  // doesn't compile: int32 isn't a collection
  • The maxCount overloads of RegisterField and RegisterOptionalField require the field type to be a collection (INOTESCollection), so a cap on anything else is a compile error.
  • A field cap covers the field's own collection only. Inner collections get their caps from their own definitions, so nothing restates the nesting. Suffixes bind left to right: int32[<=4][<=2] is at most 2 rows of at most 4 values.
  • If a field is capped and its collection definition is capped too, the two must be exactly equal, or RegisterField throws ArgumentException. Whether a field may narrow its definition's cap, and whether nodes with different caps should be able to talk, are open (I-48).
  • A collection descriptor holds only the cap: registering fields on it throws, and giving one to a type that isn't a collection is refused by NOTES.
  • Collections compare by structure, not by class name: a CatList and any other “Cat, at most 16” definition are the same NOTES type.
  • A capped definition enforces its cap in its own ToBytes/FromBytes too, and so does a field cap in the plain (non-NOTES) serializer, so caps hold on raw events as well.
  • A cap tells an endpoint without a heap exactly how much to preallocate.

Optional fields

A field registered with RegisterOptionalField may be null, which is sent as absent. The field is marked ? in the signature, so optional and required are different types (commit c1f7363):

public class Order : IBinaryConvertible
{
    public BinaryConvertibleInt32 Id { get; set; } = 0;
    public BinaryConvertibleString? Note { get; set; }                  // may be null
    public BinaryConvertibleCollection<Cat>? Cats { get; set; }         // may be null
    ...
    static Order()
    {
        d.RegisterField("Id", (Order x) => x.Id);
        d.RegisterOptionalField("Note", (Order x) => x.Note, (x, v) => x.Note = v);
        d.RegisterOptionalField("Cats", (Order x) => x.Cats, (x, v) => x.Cats = v, maxCount: 4);
    }
}
// Order{Cats:Cat[<=4]?,Id:int32,Note:string?}
  • Any field can be optional: a leaf, a record or a collection. Collection elements can't be null.
  • On the wire it's one byte (0 absent, 1 present) followed by the value when present. Any other byte value is malformed.
  • Reading needs the setter: an absent field is set to its default if it has one (Documenting fields), otherwise to null (clearing a stale value), and a present one gets a newly created instance.

Documenting fields: description, range, default

Every RegisterField and RegisterOptionalField returns a builder that documents the field it just registered. None of this is part of the NOTES type, and none of it is enforced, with one exception: the default of an optional field.

static Thermo()
{
    d.RegisterField("Celsius", (Thermo x) => x.Celsius)
        .Description("temperature in degrees Celsius").Range(-40, 125);
    d.RegisterOptionalField("Label", (Thermo x) => x.Label, (x, v) => x.Label = v)
        .Description("sensor label").Default("unnamed");
    d.RegisterOptionalField("Samples", (Thermo x) => x.Samples, (x, v) => x.Samples = v)
        .Description("readings averaged").Range(1, 100).Default(1);
    d.RegisterOptionalField("Where", (Thermo x) => x.Where, (x, v) => x.Where = v)
        .Description("where the sensor is").Default(new Spot { Floor = 0, Room = "hall" });
}

// and on the endpoint itself:
node.HookEvent("Reading", (Thermo t) => Show(t), "a room temperature reading, sent every minute");
node.RegisterFunction("Setpoint", (Spot s) => Target(s), "the target temperature for a spot");
Builder callMeaning
.Description(text)Intent, unit, anything a reader of the type should know.
.Range(min, max)The bounds the value is meant to stay in, as decimals; either may be null. For a string or a collection it is the length. Not enforced: a value outside it is sent and received normally. A record has no range (ArgumentException), and neither does min > max.
.Default(value)Typed as the field. On an optional field, a value that arrives absent is set to a fresh copy of it instead of null, in the NOTES layout and the plain layout alike. The default is the reader's: it comes from the receiving node's own registration, so a node whose type has no default still reads null. On a required field it is documentation only. The value is copied when registered.

Because documentation isn't part of the type, two programs whose types have the same shape agree even if they document them differently (harness U16, N70). The documentation travels with the agreed type instead: a proposal carries its proposer's field documentation (NOTESEventDescriptor.InputAnnotations, ReturnAnnotations) and endpoint description (the optional last argument of HookEvent and RegisterFunction), and the network keeps what the agreed descriptor came with. The first node to agree an ID documents it; a later node with other wording still joins, and its wording is not used. Within one application the types usually come from one place anyway.

Defaults are written as JSON values (numbers as numbers, strings as strings, records as objects), ranges as numbers. The same object appears in NOTESDescriptor.ToString() for a live type and in NOTESSignatureJson.ToJson(signature, annotations) for a signature. NOTESFlexibleSerDes.For(value).Annotations lists a type's documentation, one NOTESFieldAnnotation (Record, Field, Description, Min, Max, Default) per documented field.

Recursive types

A record may contain itself, directly or through other types, as long as the cycle passes through a collection or an optional field: either one lets a value end. The signature just refers to the type by name. A tree, through a collection:

public class TreeNode : IBinaryConvertible
{
    public BinaryConvertibleInt32 Value { get; set; } = 0;
    public BinaryConvertibleCollection<TreeNode> Children { get; set; } = new();
    public override string Name => "TreeNode";
    private static readonly NOTESDescriptor d = new();
    public override NOTESDescriptor Descriptor => d;
    static TreeNode()
    {
        d.RegisterField("Value",    (TreeNode x) => x.Value);
        d.RegisterField("Children", (TreeNode x) => x.Children);   // fine inside TreeNode's own static constructor
    }
    public override bool FromBytes(ref Span<byte> data) => d.FromBytes(this, ref data);
    public override byte[] ToBytes() => d.ToBytes(this).ToArray();
}
// Signature: =TreeNode
//            TreeNode{Children:TreeNode[],Value:int32}

A linked list, directly through an optional field:

public class LinkedNode : IBinaryConvertible
{
    public BinaryConvertibleInt32 Value { get; set; } = 0;
    public LinkedNode? Next { get; set; }                               // null ends the list
    public override string Name => "LinkedNode";
    private static readonly NOTESDescriptor d = new();
    public override NOTESDescriptor Descriptor => d;
    static LinkedNode()
    {
        d.RegisterField("Value", (LinkedNode x) => x.Value);
        d.RegisterOptionalField("Next", (LinkedNode x) => x.Next, (x, v) => x.Next = v);
    }
    public override bool FromBytes(ref Span<byte> data) => d.FromBytes(this, ref data);
    public override byte[] ToBytes() => d.ToBytes(this).ToArray();
}
// Signature: =LinkedNode
//            LinkedNode{Next:LinkedNode?,Value:int32}
  • Registering the type being defined, or a collection of it, inside its own static constructor is safe. Mutual recursion (A{B:B?}, B{A:A}) works too, whichever static constructor runs first.
  • A cycle made only of required record fields would make every value infinite, and is refused (NOTESTypeException, with the cycle in the message). The check runs over the whole type graph, so it doesn't depend on which type is the event's root or on registration order.
  • NOTES sends a tree, not a graph. A value that shares a subtree writes it once per occurrence, and a cyclic object graph (a list whose last node points back to the first) can't be sent: it hits the nesting limit and FireEvent returns false.
  • Values can nest at most NOTESFlexibleSerDes.MaxNestingDepth levels (256 by default, process-wide). Each collection and each present optional field is one level, so that's also the longest linked list. Deeper values are refused when sending and dropped when receiving.

Signature grammar

signature = entry*                           ; sorted ordinally (UTF-16 code units)
entry     = "=" TypeRef                      ; the event's root type, exactly one
          | Name "{" field ("," field)* "}"  ; one per record type, fields sorted
field     = FieldName ":" TypeRef ["?"]              ; "?" marks an optional field
TypeRef   = LeafName | RecordName
          | TypeRef "[]"                     ; collection
          | TypeRef "[<=" N "]"              ; capped collection
CharactersStatus
{ } [ ] : , =Delimiters of the grammar above.
|Reserved for polymorphism (tagged unions), which is deliberately left out of the wire protocol for now.
?Marks an optional field (after the whole TypeRef: Cats:Cat[<=4]?).
< >Used by caps. Ranges and defaults are documentation, not part of the type, so they don't appear in signatures (Documenting fields).
@Reserved.

Names must be non-empty and free of these characters and of control characters. Within one event, a record name has exactly one definition, a name can't be both a leaf and a record, and two different C# leaf types can't share a name.

Reading untrusted input

A typed message comes from any node on the network, so the NOTES reader validates everything and drops the message (the handler isn't called) instead of throwing:

InputResult
Negative count, count above the cap, count above the remaining bytesdropped; nothing allocated for it
An element that consumes no bytesdropped; this bounds the total work by the message size
More than MaxNestingDepth nested collections and present optional fields, or too little stack leftdropped, never a stack overflow
An optional field's presence byte other than 0 or 1dropped
Truncated input, or a malformed leaf (for example a string length past the end)dropped
Bytes left over after the valuedropped (the layouts can't really match)

Harness U08 feeds these cases in, including a 200,000-level nesting attack and a count of 50 million in an 8-byte message. U09 covers the types NOTES refuses to describe, U11 the caps, and U12 optional fields and a 200,000-deep chain of present flags. The plain (non-NOTES) FromBytes of a type returns false instead of overflowing the stack too.

Inspecting a type

// Structure (JSON-like)
Console.WriteLine(new CatDescriptor().Descriptor.ToString());
// Values
Console.WriteLine(new CatDescriptor("Tom", 1, 3, "Attila"));      // uses descriptor.ToString(this)

// The signature NOTES will negotiate, and the canonical bytes
var notes = NOTESFlexibleSerDes.For(new CatDescriptor());     // throws NOTESTypeException if not describable
foreach (var entry in notes.Signature) Console.WriteLine(entry);
// =Cat
// Cat{Age:UInt64,ID:UInt64,Name:string,Owner:string}
byte[] bytes = notes.ToBytes(new CatDescriptor("Tom", 1, 3, "Attila"));

NodeA in the Examples uses the same technique to print the signature of NOTESTEstObject. Descriptor.ToString() prints the same structure as indented JSON, and Descriptor.ToString(value) a value (a signature that arrived over the network can be turned into the same JSON shape without the C# type: NOTESSignatureJson, see Namespace node).
