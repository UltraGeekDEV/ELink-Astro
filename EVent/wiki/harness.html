EVent.Harness is a console project in the repo (EVent.Harness/) that drives the unmodified library from the outside and tries to make it fail. It runs every scenario in its own child process with a hard timeout, so deadlocks and process crashes are recorded as results instead of ending the run. The library's code was not changed; the harness only reads private state through reflection, to check what nodes believe.

Running it

dotnet run --project EVent.Harness                       # everything (~5 minutes)
dotnet run --project EVent.Harness -- N24 C0             # prefix filter
dotnet run --project EVent.Harness -- N24 --repeat=10    # flakiness
dotnet run --project EVent.Harness -- list

Results go to harness-results/results.md and results.json. See EVent.Harness/README.md for how to write a scenario.

Test rig

  • In-memory transport. MemStream is an IStreamClient whose frames are parsed by the library's own Package.ReadPackage. It can simulate a cable pull, a half-open link (writes fail while reads stay open), latency, and hostile raw bytes. MemProtocol is an ICommsProtocol over it, so real TryEstablishConnection merges run without sockets.
  • Real TCP on loopback for the T* scenarios.
  • EVent's Debug.WriteLine output is captured and attached to failing results.
  • Environment: .NET 8.0.425 SDK on Linux x64. Timing-sensitive scenarios were repeated 5 times, and the thread-pool hypothesis was tested with EVH_MINTHREADS=64.

Headline findings

Fixed: NOTES data corruption under concurrent first use (was I-39, commit e2e550c)

When two nodes first hooked the same event at the same moment, with the same type declared in different field orders, nodes could decode garbage (Age = 535206337294893059) or disagree on the field order. Typed-event signatures are now sorted into a canonical order, descriptor equality is exact, and the proposing node registers against the agreed descriptor. The before/after measurement used N24 (5 runs × 30 rounds), with the route-wait in place:

Fixed: poisoned event IDs after failed or interrupted agreements (was I-07, commit 7e35633)

Contested proposals of incompatible types, or a proposer dying before Finalize, used to leave pending proposals behind forever, so the event ID could never be used again. Finalize now carries the full proposal, a failed proposer sends Abort, and pending proposals expire after a TTL.

Fixed: endless HookEvent retry on nodes deep inside a merged network (was I-06 and I-14, commit 6bbe9c2)

After two established networks merged, only the two nodes at the ends of the new link learned the other side's descriptors. A deeper node that hooked such an event was told “already established”, which it treated as “busy”, and retried forever: N28 measured 198 identical retries in 20 s, and handing the node the missing descriptor ended the loop within 70 ms. Now the reply distinguishes Established (adopt it) from Pending (retry), and the endpoint nodes re-share every descriptor with the whole merged network.

Fixed: a merge no longer costs the target network per event (commit e5b2492)

After a link came up, each endpoint queried every ID in the peer's event list with its own network-wide call, re-sent every descriptor it knew one call at a time, and did it all twice, because each link exchanged its event lists twice. Every entry of every list also re-flooded an EventAdded through the whole network. Now the list goes once each way, known events aren't re-announced, and descriptors travel in one batched call per side.

Fixed: thread-pool starvation, handlers on the link reader, the gate race (was I-42, I-04, I-17; commit 2c9a853)

The library used to park a thread for every wait (CallFunction's wait handle, .Result and .Wait() in merges and agreement), and ran function handlers, typed callbacks included, on the reader of the link that delivered them. Blocked callers then took the thread pool that the links' own read loops need. Now every wait inside the library is an await, each operation has an …Async form, handlers run as pool tasks (async ones hold no thread while they await), and the gate is async and race-free. The blocking forms remain as wrappers.

Typed merges can't close a loop, whatever the latency (commits f7f66a8, 8c7a5cf)

TryEstablishConnection pings only its own group, once. Every node answers with its own merges in flight, and a probe on the target answers with its owner's number, so of any two merges in flight at least one sees the other when its ping completes. Our own number coming back means a loop. The target network is never frozen and never sees the ping. The first version (f7f66a8) kept expiring records refreshed by a beacon and checked in timed listening windows: joins took about 0.8 s, and with 300 ms links inside a group two merges could both go through, closing a loop (found by an independent review).

Fixed: calls, discovery and the start-up poll no longer block forever (was I-03, commit a00a3a4)

Back-pressure

Raw events used to queue without limit (a publisher on a slow link enqueued 328,000 events in 2 s while 241 were delivered, and the heap grew by 360 MB). Now each queue holds at most QueuedClient.MaxQueuedDataBytes of them: the publisher waits, the link stops reading, and nothing is lost (C24).

What held up well

  • Basic routing and dRPC across chains, including 3,200 concurrent calls with zero wrong answers (C11) and correct partial results when one of several providers drops (C09).
  • NOTES field reordering works, including nested child types (N01, N02). Conflicting merges are refused (N13), as are conflicting proposals (N04).
  • An 8-node network grown one join at a time delivers to all 7 subscribers (N22). A 20 MB payload goes through (C18). Typed events work over real TCP (T01), and a subscriber dying mid-call releases the publisher (T04).
  • Nested dRPC over a different link is fine (C07). Hook/unhook churn under fire raised no exceptions (C16), and a half-open link is cleaned up without crashing (C23).

Corrections to the code review

Running the code proved a few code-reading claims wrong or overstated. The issues page now says so:

  • No handshake echo (I-18, I-28): a node doesn't route its own events back to the peer after a link comes up (C14). The four ListEvents per link are real.
  • Remote-only conflicts are caught: hooking an event that the other network uses with another type fails (N14). Depending on timing it fails either cleanly or with an exception, but it does fail.
  • Loops are detectable from a higher layer, as you said (C04). Typed merges now use this (N41).
