EVentNode

The router: interest tables, forwarding, admin protocol and dRPC aggregation.

namespace EVent.CoreFunctionality EVentNode.cs

The router. Use it directly for raw events, plain dRPC, tooling, or bridging. Concepts: Links & interest routing, dRPC.

Lifecycle

public EVentNode(string NodeID, params ICommsProtocol[] protocolHandlers)

Creates the node and subscribes to each transport's OnClientAccepted. It doesn't start anything; call Run().

public void Run()

Calls Run() on every transport, so they start listening and scanning.

public void Stop()

Calls Stop() on every transport, then Shutdown() on every client, local layers included. Each client's read loop then ends and removes it, which completes any call still waiting on it. A link that finishes dialing afterwards is closed instead of accepted. Calling it again does nothing.

public LocalCallbackClient AddLocalCallbackLayer()

Creates a LocalCallbackClient, attaches it as a client, and returns it. Can be called at any time, whether or not the node is already linked to others: the new layer asks for the node's current event list itself and learns it before returning control to the node's read loop (commit 2d1d400). Several local layers per node are allowed.

public void AcceptClient(IEVentClient client) public void AcceptClient(IEVentClient client, bool adopted)

Attaches any client: registers it, sends InterconnectRunning, and starts its read loop. Transports call this for you. Use it directly to plug in a custom IEVentClient. With adopted, the link's handshake already happened with a previous owner (see DetachClient): the node also sends its event list straight away, because the peer won't announce InterconnectRunning again. The peer still answers with its own list.

public void DetachClient(QueuedClient client)

Hands a live link over to another node: stops reading it (without consuming a package) and forgets it here, without closing it or telling the peer. Packages that arrive meanwhile wait in the link until the next owner reads them. TypeSafeEVentNode uses it to turn its merge probe into the real link.

Properties

public string NodeID { get; private set; }

A free-form name. Never transmitted (I-38).

public ICommsProtocol[] protocolHandlers { get; protected set; }

The transports passed to the constructor.

public const int ProtocolVersion = 1; public const int MinimumProtocolVersion = 1; public static LinkHandshake Handshake { get; } public IReadOnlyList<LinkHandshake> PeerHandshakes()

The link protocol's version. Each end of a link sends its LinkHandshake (version, oldest version accepted, implementation: "EVent.NET", or "evn-cpp" for a C++ leaf) in InterconnectRunning; a peer outside the range is refused with a LinkFault naming both sides (harness C39). PeerHandshakes lists what the current links' peers said.

Observing the network

public void OnConnected(Action<BinaryConvertibleCollection<BinaryConvertibleString>> handler)

Raised when a ListEvents arrives: once per link handshake, and again whenever this node sends QueryEvents itself. The argument is the peer's event list. Runs on the link's reader thread.

public void OnEventAdded(Action<string> handler) public void OnEventRemoved(Action<string> handler)

Raised when this node processes an EventAdded / EventRemoved. For additions this happens when the event is new to this node (repeated announcements are dropped). For removals it happens when the last interested client is gone.

public void OnLinkFault(Action<LinkFault> handler) public static TimeSpan LinkFaultFlushTimeout { get; set; } // default 2 s

Raised when a link delivered something malformed and was dropped, by this node or by the peer (which says why first). LinkFault has ClientID, Reason, ReportedByPeer, LinkDropped (false only for the local layer, which is never dropped), Redial (the connection info this node dialed the link with, or null) and Exception. Handler exceptions are caught. See Faults and re-joining.

public void OnDataReceived(Action<Package, Action<Package>> handler)

Raised for every non-admin, non-function package this node processes, including packages in transit. The second argument is a no-op placeholder (I-29).

node.OnDataReceived((pkg, _) => Console.WriteLine($"{pkg.EventID}: {pkg.Data.Length} bytes"));
public void OnFunctionCall(Func<EVentFunction, EVentFunction>? handler)

Runs when any dRPC call completes on this node, whether initiated here or forwarded. A non-null return value replaces the aggregated result (I-37).

public IEnumerable<string> GetEvents()

A snapshot of the EventIDs somebody (local or remote) is interested in. Not locked (I-19).

public const string PrefixWildcard = "*"; public static bool IsPrefixRoute(string eventID) public static IEnumerable<string> CoveringPrefixRoutes(string eventID)

An interest entry ending in .* is a prefix route: everything under the prefix is routed to the client that announced it. IsPrefixRoute("Minecraft.*") is true; CoveringPrefixRoutes("Minecraft.Player.Health") gives Minecraft.* and Minecraft.Player.*, the entries a node looks up besides the ID itself. SendData, calls and GetEvents all see prefix routes like any other entry.

Sending

public async Task SendData(Package package, IEVentClient? receivedFrom = null)

Routes a package to every client interested in package.EventID, except receivedFrom. This is the low-level way to inject traffic. Most code should use LocalCallbackClient.FireEvent.

public Task<List<TResult>> CallFunctionAsync<TResult, TInput>(string EventID, TInput parameters, TimeSpan? timeout = null, CancellationToken cancellationToken = default) public List<TResult> CallFunction<TResult, TInput>(… the same …) public static TimeSpan FunctionCallTimeout { get; set; } // default 30 s where TResult : IBinaryConvertible, new() where TInput : IBinaryConvertible, new()

Calls function EventID on every provider in the network and completes when all have answered or disconnected. CallFunctionAsync holds no thread while it waits; CallFunction blocks its caller (prefer the async form for many concurrent calls, see Threading). Returns one element per answer that could be deserialized as TResult. Returns an empty list immediately if there are no providers. If some providers haven't answered within timeout (default FunctionCallTimeout), the call completes with the answers collected so far, just as if those providers had dropped out; a late answer is ignored (C36). Answers still held by a node in between that is itself waiting on a slow provider are among the missing ones. Calls this node forwards for others expire after FunctionCallTimeout too, so a provider that never answers leaves nothing behind on the path (C37). Cancelling cancellationToken abandons the call with an OperationCanceledException (C38). FunctionCallTimeout is process-wide; Timeout.InfiniteTimeSpan waits forever. Note the generic order (I-34).

var loads = node.CallFunction<BinaryConvertibleFloat, NOTESVoid>("GetCpuLoad", NOTESVoid.Void);
Console.WriteLine($"max load {loads.Max(l => l.value)}");
public Task<List<TResult>> CallFunctionAsync<TResult, TInput>(string EventID, TInput parameters, Func<TInput, byte[]> customInputSerializer, Func<TResult, byte[], bool> customResultDeserializer, TimeSpan? timeout = null, CancellationToken cancellationToken = default) public List<TResult> CallFunction<TResult, TInput>(… the same …)

The same, with caller-supplied (de)serializers. This is what TypeSafeEVentNode.FireEvent uses. An answer the deserializer can't read (or throws on) is left out; the call still completes.

public Task CallFunctionUnacknowledgedAsync(string EventID, byte[] payload)

Delivers payload (already serialized parameters) to every provider of EventID in the network and does not wait for them: they send no answer, and this node keeps no state for the call (no handle, deadline timer or answer collection). It is what TypeSafeEVentNode.PublishEventAsync sends.

On the wire
A FunctionCall whose handle has bit 63 of the call ID set (EVentFunction). A node that knows the bit relays the frame it received unchanged and answers nothing; a node that doesn't treats it as a call and answers, and the caller ignores the answer.
Completes
When every provider's queue has accepted the call. Unanswered calls count against QueuedClient.MaxQueuedDataBytes like raw events, at every queue on the way, so a publisher faster than a link is slowed down, not buffered without bound; a relay stops reading a link while the next one is full. Calls from one node to one provider arrive in the order they were made, and a local layer runs one ID's unanswered calls one at a time, in order.
public void HandleFunctionCall(Package package, IEVentClient client)

Internal: processes an incoming FunctionCall. It's public, but calling it yourself isn't meaningful.
