Transports

TCP, UDP discovery and serial links, and how to add your own.

A transport is an ICommsProtocol. It produces QueuedClient links for the node, and each link wraps an IStreamClient that moves framed packages. Pass any number of transports to a node's constructor.

ICommsProtocol.cs / IStreamClient.cs
public interface ICommsProtocol
{
    void OnClientAccepted(Action<QueuedClient> action);          // node subscribes to inbound links
    void Run();                                                  // start listening / scanning
    Task<QueuedClient?> EstablishInterconnect(Package package);  // dial out, or return null if not mine
    void Stop();
}
public interface IStreamClient
{
    Task Send(byte[] data);           // write one serialized Package
    Task<Package?> ReadPackage();     // next full Package; null means the link is closed
    void Close();
}

EstablishInterconnect is called with the whole CreateInterconnect admin package. Its Data contains a nested Package whose EventID names the connection type (ConnectionTypes.*) and whose data holds the parameters. Every transport on the node is asked, and each returns null unless the request is for it.

TCP

TCPServer(IPAddress listen, int port, params string[] serverBroadcastedIDs) listens for inbound TCP links and, for each ID given, runs a ServerTCPBroadcast responder so other nodes can find it by name. Run binds the port (and throws if it's taken); Stop releases it and stops the responders, and the server can be started again.

Creating TCP interconnects
// Direct: this node's TCPServer listening on 5699 dials 192.168.1.20:5698
var direct = new TCPConnectionData { TargetIP = "192.168.1.20", TargetPort = 5698, SourcePort = 5699 };
node.TryEstablishConnection(new Package(ConnectionTypes.TCP, direct));

// Discovery: find whoever advertises "NodeA" on the LAN
node.TryEstablishConnection(new Package(ConnectionTypes.TCPDiscovery, "NodeA"));

UDP multicast discovery

The reply payload is a BroadcastHandshake: 4 bytes of IPv4 address, a 2-byte port (big-endian), and a CRC-32 (little-endian) over those 6 bytes. The advertised IP is TCPServer.AdvertisedAddress if set, else the listening address if it's a specific IPv4 address, else IPUtils.GetLocalIPv4() (which falls back to an interface address, then loopback, on machines without a default route). The client re-sends its request every second (ClientTCPDiscovery.RetryInterval) and ignores replies for other IDs.

If nobody answers, the client gives up after ClientTCPDiscovery.Timeout (10 s by default) and the dial fails. TryEstablishConnection stops waiting for it after MergeStepTimeout.

Serial

SerialServer(string ServerID) scans SerialPort.GetPortNames() once a second. For each new port, it opens the port at 9600 baud and runs a handshake. If the handshake succeeds, the port becomes a link. Serial is accept-only: EstablishInterconnect always returns null.

A device that wants to join an EVent network over serial must:

  1. Speak the Package framing at 9600 baud.
  2. Echo the SerialHandshake package with the same server ID, then answer SetBaudrate with its desired baud rate (int32, little-endian), and switch to that rate.
  3. Then take part in the normal link handshake (InterconnectRunning, ListEvents, …) and answer FunctionCalls for anything it registers.
Serial caveats

Current limitations: the link is dropped after about 1 s without incoming data and is never re-established (I-09); packages over 246 bytes crash the reader (I-16); ports that fail the handshake are probed again every second (I-22).

QueuedClient: the link wrapper

QueuedClient QueuedClient.cs is what the node sees for every remote link. Send enqueues into a channel (raw events are limited to MaxQueuedDataBytes of them: the sender's task waits for room), and a background pump (EmptyQueue) serializes each package and writes it to the stream. A package with an empty EventID is dropped, which is how Shutdown() wakes the pump so it can exit. If a write fails, the pump closes the stream, and the read loop then ends and removes the client. ReadPackage delegates to the stream client.

Writing a new transport

To add a transport (WebSocket, BLE, named pipes, …) you implement two small interfaces. For stream-shaped media, Package.ReadPackage(Stream) already does the framing for you.

Sketch: a named-pipe transport
using EVent.Connections;
using EVent.Connections.Models;
using EVent.Connections.Models.BaseBinaryConvertibles;
using EVent.CoreFunctionality;
using System.IO.Pipes;

// 1. Byte stream <-> Package
class PipeStreamClient : IStreamClient
{
    private readonly Stream stream;
    public PipeStreamClient(Stream s) => stream = s;
    public Task Send(byte[] data) => stream.WriteAsync(data).AsTask();
    public Task<Package?> ReadPackage() => Package.ReadPackage(stream); // null => closed
    public void Close() => stream.Dispose();
}

// 2. Accept and dial
class PipeProtocol : ICommsProtocol
{
    public const string ConnectionType = "PIPE";         // your own connection-type ID
    private Action<QueuedClient>? accepted;
    private readonly string pipeName;
    private volatile bool alive = true;
    public PipeProtocol(string pipeName) => this.pipeName = pipeName;

    public void OnClientAccepted(Action<QueuedClient> action) => accepted += action;

    public void Run() => Task.Run(async () =>
    {
        while (alive)
        {
            var server = new NamedPipeServerStream(pipeName, PipeDirection.InOut,
                NamedPipeServerStream.MaxAllowedServerInstances, PipeTransmissionMode.Byte, PipeOptions.Asynchronous);
            await server.WaitForConnectionAsync();
            accepted?.Invoke(new QueuedClient(new PipeStreamClient(server)));
        }
    });

    public async Task<QueuedClient?> EstablishInterconnect(Package createInterconnect)
    {
        var info = new Package();
        Span<byte> bytes = createInterconnect.Data;        // nested connection-info package
        if (!info.FromBytes(ref bytes) || info.EventID != ConnectionType) return null;

        var target = new BinaryConvertibleString();
        Span<byte> p = info.Data;
        if (!target.FromBytes(ref p)) return null;

        var client = new NamedPipeClientStream(".", target.Text, PipeDirection.InOut, PipeOptions.Asynchronous);
        await client.ConnectAsync(5000);
        return new QueuedClient(new PipeStreamClient(client));
    }

    public void Stop() => alive = false;
}

// usage
var node = new TypeSafeEVentNode("P1", new PipeProtocol("ev-p1"));
node.TryEstablishConnection(new Package(PipeProtocol.ConnectionType, "ev-p2"));
Note

This sketch follows the contracts the existing transports rely on, but it hasn't been compiled against the project. Things to preserve: ReadPackage must return a complete package or null (never time out with null unless the link really is dead, see I-09), and EstablishInterconnect must return null quickly for connection types that aren't yours, because every transport is asked.

Legacy: TCPClientConnection

TCPClientConnection is a standalone client from before the routing refactor. It predates ICommsProtocol, sends the unhandled "DisconnectClient" admin ID, and isn't used by the node. Treat it as dead code (I-29).
