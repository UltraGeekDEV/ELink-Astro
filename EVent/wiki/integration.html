How EVent and NOTES fit together

NOTES is a layer on EVent that uses EVent's own dRPC for both its control plane and its data plane.

The short version

NOTES is built out of EVent. TypeSafeEVentNode owns an ordinary EVentNode and LocalCallbackClient, and implements all its behaviour with EVent's own primitives:

  • The control plane (agreement, merge, pause) is a set of dRPC functions.
  • The data plane (typed events) is also dRPC: each typed event is a function returning NOTESVoid, called with a custom serializer.

In the other direction, EVent depends on NOTES' descriptor type: NOTESDescriptor is the serialization engine for EVent's own composite structures (EVentFunction, EVentFunctionHandle, NOTESEventDescriptor), and every IBinaryConvertible must expose one. NOTESDescriptor therefore has two jobs: it's the reflection-free serializer for the whole library, and it's the source of type signatures for NOTES.

Consequences for users

Because……therefore
Typed events are dRPC callsFireEvent blocks until every subscriber has run its handler. One slow subscriber stalls every publisher of that event, up to the call timeout (FunctionCallTimeout, 30 s by default, or per call); a stuck one then no longer holds it up (N69).
Typed callbacks run as thread-pool tasksA callback may fire other typed events, even back to the publisher. An async callback (Func<T, Task>) holds no thread while it awaits, and the publisher's FireEvent completes when it's done.
Events and functions share one ID namespaceDon't use the same ID with raw LocalCallbackClient.HookEvent and typed events: the raw subscriber answers the typed call with nothing, so it never gets the event.
The typed layer hides its EVentNodeYou can't mix raw events or plain functions into a TypeSafeEVentNode. To combine them, run a separate EVentNode in the same network.
The merge checks for NOTESQueryDescriptorSetTryEstablishConnection refuses to join networks that don't run NOTES. A plain EVentNode can still dial into a NOTES network (inbound links aren't checked).
NOTES functions are ordinary dRPCAny node, including a plain EVentNode, can call QueryDescriptors for diagnostics, and also NOTESShareDescriptors, StopEvents and the rest, so there's no access control.

Choosing a layer

NeedUse
Typed pub/sub between independently written programsTypeSafeEVentNode
High-rate, fire-and-forget telemetry where acknowledgements are too costlyEVentNode + LocalCallbackClient raw events (you're responsible for keeping layouts in sync)
“Ask everyone” queries with return valuesTypeSafeEVentNode.CallFunction<TIn, TOut> + RegisterFunction<TIn, TOut> (typed); EVentNode.CallFunction + LocalCallbackClient.RegisterFunction for raw bytes
Using events without writing classes for them (tools, generic bridges, scripts)NON dynamic objects: GetEndpointAsync, *Dynamic calls on TypeSafeEVentNode
Grouping an application's events under a name, and routing them as one entryNamespaceNode, with imports for what it uses from outside
Controlling what crosses between two networksFirewallNode
Connecting two applications that weren't written for each otherThe scripting node
A C++ program in the networkA C++ leaf (evn::Leaf) linked to a local C# node
Tooling, monitoring, bridgingA plain EVentNode with OnDataReceived / OnEventAdded, optionally calling QueryDescriptors; NetworkDirectory and NamespaceDirectory list what the network offers
