Scripting node

Connect applications that were never written for each other: pick an event, pick what it should drive, write the few lines in between, and they run on the network.

The scripting node is a typed node with a small web page (project EVent.Scripting). The page lists everything the network offers. You choose one input (an event to react to, or a function to answer) and any number of outputs (events to fire, functions to call). The node generates a frame: C# classes for every type involved, written from the network's agreed NON types and documented with their descriptions, ranges and defaults, and the signature of a Handle method. You write the body of Handle (or have an AI write it from the frame); the node compiles it with Roslyn and registers it as a handler. Nobody writes a DTO, and the applications on either side don't change.

Running it

var scripting = await ScriptingNode.StartAsync("Scripts", port: 5780, storeDirectory: "/var/lib/event/scripts",
    new TCPServer(IPAddress.Any, 5790, "Scripts"));
scripting.Node.TryEstablishConnection(networkInfo);     // an ordinary typed node: join it anywhere
Console.WriteLine(scripting.Web.PageUrl);               // http://127.0.0.1:5780/?token=...

Or, to try it with a ready-made network (a sensor firing Reading every few seconds, Hvac.Setpoint, Alerts printed to the console, the Minecraft and Chat namespaces):

dotnet run --project EVent.Harness -- scripting-demo

Without the page, ScriptHost does the same from code: new ScriptHost(node), then ListEndpointsAsync, GenerateFrameAsync(input, outputs), CheckAsync (compile only), DeployAsync(input, outputs, body, name, replaceId), Scripts, Remove(id), and with a store StartRestoring(). ScriptingWebHost.StartAsync(host, port) puts the page in front of any host.

The page

PartWhat it does
NetworkEvery endpoint of the node's network with its kind (event, function, untyped), type and description, filterable; each one's NON type on request. In picks the input, Out the outputs. Untyped endpoints (raw events with no agreed type) can't be picked.
FrameGenerated, read-only. Copy frame; Copy for AI copies a ready prompt: the task, the frame, and the endpoints' NON types as JSON.
BodyThe statements inside Handle. Paste (a fenced code block from an AI is unwrapped), Copy, Clear; Tab indents, Ctrl+Enter deploys. Compile errors list under it with their line in the body; clicking one jumps there.
RunningThe deployed scripts with their runs, failures and last error, refreshed every few seconds; stored scripts that can't run yet are marked waiting with the reason. Edit loads a script's selection and body; deploying then replaces it (the new one is running before the old one goes). Remove unregisters it.

The frame

For Reading (an event of Thermo) in, and Alerts (an event of Alert) and Hvac.Setpoint (a function from Spot to Thermo) out, the frame reads, shortened:

// Endpoints:
//   in   Reading: event of Thermo — a room temperature reading, sent every few seconds
//   out  Alerts: event of Alert — alerts for the people in the house
//   out  Hvac.Setpoint: function Spot -> Thermo — the target temperature for a spot
namespace EVentScript
{
    /// <summary>NON record <c>Thermo</c>, used by Reading (event), Hvac.Setpoint (answer).</summary>
    public sealed class Thermo : NONRecordView
    {
        /// <summary><c>Celsius</c>: float. temperature in degrees Celsius. Range: -40 to 125 (not enforced).</summary>
        public float Celsius { get; set; }
        /// <summary><c>Label</c>: string, optional. sensor label. Default: "unnamed" (what an absent value reads as).</summary>
        public string? Label { get; set; }
        /// <summary><c>Where</c>: Spot, optional. where the sensor is. ...</summary>
        public Spot? Where { get; set; }
        ...
    }
    public sealed class Spot : NONRecordView { ... }
    public sealed class Alert : NONRecordView { ... }

    public static class Script
    {
        public static async Task Handle(Thermo input,
            Func<Alert, Task<bool>> fireAlerts,
            Func<Spot, Task<IReadOnlyList<Thermo>>> callHvac_Setpoint,
            CancellationToken cancellation)
        {
            // ▶ your code goes here
        }
    }
}

and a body that turns hot readings into alerts:

if (input.Celsius <= 28)
    return;
var room = input.Where ?? new Spot { Room = "unknown" };
var target = await callHvac_Setpoint(room);
await fireAlerts(new Alert
{
    Message = $"{room.Room} is {input.Celsius} °C (setpoint {target.FirstOrDefault()?.Celsius})",
    Level = input.Celsius > 35 ? 2 : 1
});
  • One class per record type. A record several endpoints use (the same name and shape) is one class, so a value from one endpoint goes straight into another (input.Where above is the Spot that Hvac.Setpoint takes). Two records with one name and different shapes become Name and Name_2.
  • Members. int32, UInt64, float, string are int, ulong, float, string; an optional field is nullable; a record is its class; a list is a NONListView<T> (an IList<T> that writes through); Void is Nothing; an application's own leaf is its C# class (the scripting node must have it registered with NONLeaves). Every class wraps a NONObject (Raw), so a value is sent without any copying or serialization code.
  • The signature. input is what arrived. An output event is a Func<T, Task<bool>> (the fire); an output function a Func<TIn, Task<IReadOnlyList<TOut>>> (every provider's answer). If the input is a function, Handle returns Task<TAnswer>: the answer to the caller, null for none. cancellation is cancelled when the script is removed or replaced.
  • Documentation. Descriptions, ranges and defaults become XML comments, and the endpoint descriptions sit in the header and the parameter comments: what a person or an AI needs to write the body.

How a script runs

The frame and the body are compiled together with Roslyn, in memory, into an assembly of their own, loaded in a collectible context so a removed or replaced script can be unloaded. A generated entry point sits between the node and Handle: it wraps the NONValue that arrived in the input class, and each Func turns the class back into a NONValue and calls the node's dynamic API (FireEventDynamicAsync, CallFunctionDynamicAsync). The script is registered like any handler (HookEventDynamicAsync, or RegisterFunctionDynamicAsync for a function input), so a publisher's FireEvent completes when the script does, and the usual call timeouts apply.

An exception in a script is caught: it counts as a failure, is shown on the page with its message, and a function input gets no answer from that run. The node and the other scripts carry on (harness X07). A script that never finishes can't be stopped, only abandoned: the publisher's timeout ends its wait.

Persistence

With a store folder (the storeDirectory of ScriptingNode.StartAsync, or new ScriptHost(node, new ScriptStore(folder))), every deployed script is saved there as {id}.json: its id, name, input, outputs, body and deploy time. Files are written under a temporary name and moved into place, so a crash never leaves half a script. Replacing a script saves the new one and deletes the old; Remove deletes it; shutting the node down deletes nothing.

On start (ScriptHost.StartRestoring(), which ScriptingNode calls), the stored scripts are deployed again with their old ids. A freshly started node usually hasn't joined its network yet, so their endpoints have no agreed type: they show on the page as waiting, with the reason, and are tried again every ScriptHost.RestoreRetry (2 s) until they run, typically right after the node joins. A stored script that no longer compiles against the network's types (a type changed) keeps waiting with its first compile error as the reason; edit it, or remove it. A file in the folder that isn't a script is skipped and left alone (harness X08).

The demo keeps its scripts in the local application data folder (~/.local/share/EVent/scripting-demo on Linux).

Security

A script is code

A deployed script runs with the full rights of the scripting node's process; .NET has no sandbox. So the page listens on 127.0.0.1 only, every request needs the token made at start (it is in the printed URL; the API takes it as the X-EVent-Token header), and a request whose Host or Origin isn't that local address is refused, so a web page elsewhere can't reach the API through your browser, not even by pointing a DNS name at 127.0.0.1. Only give the URL to people you would give a shell (harness X06).

NetworkDirectory

The page's list comes from NetworkDirectory (EVent/Policy/NetworkDirectory.cs), which works from any typed node: ListAsync() returns every endpoint of the network as EndpointDescriptions, ListJsonAsync() the same as JSON. IDs routed by name are asked about in one batched descriptor query; each namespace (a prefix route) is expanded through its $Describe, nested ones included; the protocol's own IDs and $ IDs are left out. From inside a namespace it lists that namespace's IDs and its imports (X01).

HTTP API

RequestAnswer
GET /?token=…The page.
GET /api/endpointsThe catalog: id, kind, description, inputType, returnType, typed, type (the NON JSON).
POST /api/frame {input, outputs}{frame, signature, aiPrompt}, or 400 with error for an endpoint without an agreed type.
POST /api/scripts {input, outputs, body, name?, replace?}{ok, id, error, diagnostics}; 400 when it doesn't compile or can't be registered. Each diagnostic has severity, id, message, line, column, inBody.
GET /api/scripts, GET /api/scripts/{id}The running scripts with their stats; one script with its body.
DELETE /api/scripts/{id}Removes it (204).

Every /api request needs the X-EVent-Token header.

Limits

  • One input per script; any number of outputs.
  • The body is the inside of one method; local functions work, other classes don't.
  • A script may use the base library (System, LINQ, collections, tasks); it has no other packages.
  • The store keeps the current version of each script, not a history.
  • Endpoints need an agreed type; an application's own leaf types need their class on the scripting node.
