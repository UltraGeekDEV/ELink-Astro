TypeSafeEVentNode

The typed, NOTES-enabled node: the main entry point for applications.

namespace Event.CoreFunctionality TypeSafeEVentNode.cs

The high-level, typed node. It wraps one EVentNode and one LocalCallbackClient (both private) and adds NOTES. Conceptual background: What is NOTES?, Type agreement protocol.

Construction

public TypeSafeEVentNode(string NodeID, params ICommsProtocol[] commsProtocols)

Creates and starts the node: builds the EVentNode, subscribes to OnConnected, calls Run() on the transports, attaches the local layer, registers the NOTES system functions, and blocks until the node answers AwaitReady. It polls every 10 ms, normally for a few milliseconds; if the node isn't ready within StartupTimeout (process-wide, default 10 s), the constructor stops the node and throws TimeoutException.

var node = new TypeSafeEVentNode("Kitchen",
    new TCPServer(IPAddress.Any, 5698, "Kitchen"),   // TCP + discoverable as "Kitchen"
    new SerialServer("Kitchen"));                     // also accept serial devices
public string NodeID { get; }

The inner node's ID. Used only for logging.

public static TimeSpan ProposalTimeToLive { get; set; } // default 5 s

How long a proposal accepted by this node, but not yet finalized, blocks competing proposals for its event. It protects against proposers that crash or lose their link mid-agreement. It's process-wide and local policy, not sent on the wire. Because Finalize carries the full proposal, a short TTL can't break a legitimate agreement; it only weakens protection against simultaneous proposals. See recovery.

public void OnLinkFault(Action<LinkFault> handler)

The inner node's OnLinkFault. To re-join, the dialing side can call TryEstablishConnection(fault.Redial) from a background task.

public static TimeSpan MergeStepTimeout { get; set; } // default 5 s

The timeout policy of a merge: how long any single network step of TryEstablishConnectionAsync may take (reaching the target, its handshake, the merge ping, freezing our group, the descriptor query, the new link's handshake). Every step normally completes in a round trip, so this only fires when a node on the path died without its link dropping, or the target stopped answering. A timed-out step is never taken as clear. Process-wide, local policy. (Replaces ConnectProbeTimeout.)

public static int MaxMergeAttempts { get; set; } // default 6

How many timed-out steps TryEstablishConnectionAsync retries before it returns MergeResult.Timeout. Stepping aside for other merges doesn't count: that's normal contention, resolved by back-off.

Typed events

public Task<bool> HookEventAsync<TResult>(string eventID, Action<TResult> callback, string? description = null) public Task<bool> HookEventAsync<TResult>(string eventID, Func<TResult, Task> callback, string? description = null) public bool HookEvent<TResult>(string eventID, Action<TResult> callback, string? description = null) public bool HookEvent<TResult>(string eventID, Func<TResult, Task> callback, string? description = null) where TResult : IBinaryConvertible, new()

Subscribes callback to typed event eventID. description documents the event if this node's proposal becomes the agreed type (see Documenting fields); it is ignored when the type is already agreed. If the event has no agreed type yet, it negotiates one network-wide using TResult's signature. If a type is already agreed, it adopts that type and reorders fields as needed.

Returns
true once subscribed. false on a detected type mismatch, including a pending (not yet expired) proposal of another type. After a false the node has withdrawn its proposal, so retrying is safe.
Waits
While the gate is closed (during a merge), and for the one or two network-wide calls of the agreement. While an equal proposal from another node is pending it retries every 100 ms. If the type was already agreed elsewhere, for example on the other side of a merge, it adopts that descriptor immediately. HookEventAsync holds no thread while it waits; HookEvent blocks its caller (see Threading).
Callback
Runs as a thread-pool task per delivery, never on the link's reader, so it may fire events or call functions itself, even back over the link the event came from. With a Func<TResult, Task> callback the publisher's FireEvent completes when the returned task does, and no thread is held while it awaits. An exception from the callback is logged; the publisher still completes. Deliveries can arrive in any order.
Hooking twice
Allowed. Each callback is registered, and both run.
Returns when routed
It returns once the whole network routes the new subscription: the node lets its announcement travel ahead of one network-wide AwaitReady call, which every node answers only after handling what came before it on its link. An event fired anywhere after the hook returns reaches it (harness N09). Beyond a firewall or namespace node (which don't pass AwaitReady) it is still eventually consistent. SubscriptionConfirmTimeout (5 s) bounds the wait if a node stopped answering. RegisterFunction and the NON registrations do the same.
if (!await node.HookEventAsync("Orders.Created", async (OrderCreated o) => await store.SaveAsync(o)))
    throw new InvalidOperationException("Orders.Created has a different type on the network");
public Task<bool> FireEventAsync<T>(string eventID, T data, TimeSpan? timeout = null, CancellationToken cancellationToken = default) public bool FireEvent<T>(… the same …) where T : IBinaryConvertible, new()

Delivers data to every subscriber of eventID in the network and waits for all of them to finish.

Returns
true once every interested party has received it, which includes nobody being interested (an ID nobody in the network uses). false only on a type mismatch: T's signature differs from the agreed one, the ID is a typed function or used only by raw subscribers with no agreed type, or data violates the type (a null member, an exceeded cap). T may differ from the type this node hooked with, as long as the signatures match. If the network routes the ID but its descriptor hasn't reached this node yet, it's fetched and adopted first (N66, N67).
Waits
Until every subscriber's callback has finished, at most timeout (default EVentNode.FunctionCallTimeout, 30 s). A callback still running then keeps running, but no longer holds up the publisher, and the result is still true (N69). Cancelling cancellationToken stops the wait with an OperationCanceledException. FireEventAsync holds no thread while it waits; FireEvent blocks its caller.
public Task<bool> PublishEventAsync<T>(string eventID, T data, CancellationToken cancellationToken = default) public bool PublishEvent<T>(string eventID, T data, CancellationToken cancellationToken = default) where T : IBinaryConvertible, new()

Fire and forget: hands data to every link that leads to a subscriber and completes, without waiting for the subscribers or hearing back from them. No acknowledgement travels and nothing is kept per event, so streams of events (sensor readings, telemetry) move several times faster than with FireEventAsync, which is one call with answers.

Returns
true once the event was handed on, which includes nobody being interested. false only on a type mismatch, exactly as for FireEventAsync. It says nothing about the subscribers having handled the event.
Promises
Events published by one node reach each subscriber in the order they were published; a subscriber's handlers get one event ID's events one at a time, in order (a slow handler delays that ID's later events, not other IDs). A publisher faster than a link is slowed down (the task completes later), never buffered without bound (QueuedClient.MaxQueuedDataBytes, as for raw events).
Does not promise
That anything arrived: a subscriber that has gone, a link that breaks with events queued, or a handler that throws loses the event without a trace. Use FireEventAsync where the publisher has to know.
On the wire
An ordinary FunctionCall whose handle has bit 63 of the call ID set (EVentFunction). A node that knows the bit relays the received frame unchanged and sends no answer; one that does not treats it as a call and answers, and the caller ignores the answer. Peers need no new protocol version.

Typed functions

A typed function is typed dRPC: every provider in the network answers, and the caller gets all the answers. Its type is the pair (input, return), agreed network-wide exactly like an event's type. A typed event is the special case whose return type is NOTESVoid, so an ID is either an event or a function: hooking an event on a function's ID, or registering a function on an event's ID, is refused as a type conflict, and so is a second return type. See Typed functions on the protocol page.

public Task<bool> RegisterFunctionAsync<TIn, TOut>(string eventID, Func<TIn, TOut> handler, string? description = null) public Task<bool> RegisterFunctionAsync<TIn, TOut>(string eventID, Func<TIn, Task<TOut>> handler, string? description = null) public bool RegisterFunction<TIn, TOut>(string eventID, Func<TIn, TOut> handler, string? description = null) public bool RegisterFunction<TIn, TOut>(string eventID, Func<TIn, Task<TOut>> handler, string? description = null) where TIn : IBinaryConvertible, new() where TOut : IBinaryConvertible, new()

Provides function eventID: each call anywhere in the network runs handler, and its result is one entry of the caller's answer. If the ID has no agreed type yet, the pair (TIn, TOut) is proposed; if it has one, both types must match it.

Returns
true once registered, false on a type conflict (with the agreed pair, with a pending proposal of another pair, or with an event on the same ID).
Handler
Runs as a thread-pool task per call, never on a link's reader. Return null to contribute no answer. If it throws, or its result can't be serialized (a null member, an exceeded cap), the error is logged and this provider contributes no answer; the call still completes. An async handler holds no thread while it awaits. Several providers per ID, on one node or many, are allowed.
await node.RegisterFunctionAsync("Inventory.Count", (Sku s) => new Count { Value = stock[s.Id] });
public Task<BinaryConvertibleCollection<TOut>?> CallFunctionAsync<TIn, TOut>(string eventID, TIn input, TimeSpan? timeout = null, CancellationToken cancellationToken = default) public BinaryConvertibleCollection<TOut>? CallFunction<TIn, TOut>(… the same …) where TIn : IBinaryConvertible, new() where TOut : IBinaryConvertible, new()

Calls every provider of eventID in the network and waits for all of them.

Returns
One entry per provider that answered (a provider that returned null is left out; empty if there are no providers, including an ID nobody uses), or null only on a type mismatch: TIn or TOut doesn't match the agreed pair (an event's ID included), or input violates the type. Like events, the caller's types only need the agreed signatures, not the provider's classes. Answers arrive in no particular order.
Waits
Until every provider has answered or dropped out, at most timeout (default EVentNode.FunctionCallTimeout, 30 s); providers that haven't answered by then are left out (N69). Cancelling cancellationToken abandons the call with an OperationCanceledException. CallFunctionAsync holds no thread while it waits.
var counts = await node.CallFunctionAsync<Sku, Count>("Inventory.Count", new Sku { Id = "A-17" });
if (counts == null) throw new InvalidOperationException("Inventory.Count has another type on the network");
int total = counts.Sum(c => c.Value);          // one Count per warehouse that answered
public bool UnhookEvent<TResult>(string eventID, Action<TResult> callback) public bool UnhookEvent<TResult>(string eventID, Func<TResult, Task> callback) public bool UnregisterFunction<TIn, TOut>(string eventID, Func<TIn, TOut> handler) public bool UnregisterFunction<TIn, TOut>(string eventID, Func<TIn, Task<TOut>> handler)

Removes a callback or handler from this node, matched by the delegate you passed in (keep it in a variable); if it was added more than once, every registration goes. Returns whether it was there. When nothing on this node uses the ID any more, the network stops routing it here (Removing interest). The agreed type stays: it belongs to the network, so hooking or registering again later needs no new agreement (N64, N65).

Stopping

public void Stop() public void Dispose() // TypeSafeEVentNode : IDisposable

Stops the node: its transports stop accepting, every link and its local layer close, and events and calls in flight elsewhere complete without it. Anything waiting on a merge freeze is let through. Afterwards HookEvent, RegisterFunction, FireEvent, CallFunction and TryEstablishConnection throw ObjectDisposedException; so does one of them that was still in flight on this node when it stopped. Calling it again does nothing (N68, T07).

Threading

Every operation that waits for the network comes in two forms. The …Async form (HookEventAsync, FireEventAsync, TryEstablishConnectionAsync, and EVentNode.CallFunctionAsync underneath) holds no thread while it waits, so any number of them can be in flight. The blocking form waits on its caller's thread. That's fine from your own threads, a console main or a UI worker, but each blocked thread-pool thread is one the links can't use to read answers: with 32 pool threads calling the blocking FireEvent, typed events ran at about 10,000/s, and with FireEventAsync at about 43,000/s (N52). The constructor is the only other blocking wait: it waits (briefly, once) until its local registrations are routed.

Joining networks

public Task<MergeResult> TryEstablishConnectionAsync(Package connectionInfo) public bool TryEstablishConnection(Package connectionInfo) public bool TryEstablishConnection(Package connectionInfo, out MergeResult result)

Links this node's network to another one, unless the link would close a loop, the other side doesn't run NOTES, or an event has conflicting types. connectionInfo is a connection-type package understood by one of the transports:

var why = await node.TryEstablishConnectionAsync(new Package(ConnectionTypes.TCPDiscovery, "NodeA"));   // UDP discovery
if (why != MergeResult.Connected)
    Console.WriteLine($"not linked: {why}");   // AlreadyConnected, Busy, TypeConflict, ...
node.TryEstablishConnection(new Package(ConnectionTypes.TCP,
    new TCPConnectionData { TargetIP = "10.0.0.5", TargetPort = 5698, SourcePort = 5699 }));
Returns
MergeResult.Connected (or true) once the real link is up. Otherwise the reason (or false and the reason in result): see MergeResult.
Takes
A handful of round trips, spent without holding a thread: the probe's handshake with the target, one merge ping over our group, the freeze, one descriptor query, the link handshake. A few milliseconds in memory. Longer while other merges are in flight (exponential back-off). A target that discovery never finds gives up with Unreachable after MergeStepTimeout (N15).
Pauses
Typed traffic in this node's network while descriptors are aligned and the link comes up, never in the target's network.

See Merging two networks and Loop prevention.

public enum MergeResult { Connected, AlreadyConnected, Busy, TypeConflict, NotNOTES, Unreachable, Timeout }

Why TryEstablishConnection ended. AlreadyConnected means the target already reaches this network, so the link would have closed a loop. Busy means a merge in our way never ended (its node is broken); Timeout means a step timed out MaxMergeAttempts times. The full table is on the protocol page.

Missing members

There's no access to the inner EVentNode. The node starts in its constructor; there is no Run. The handlers of the StopEvents and AllowEvents system events are private: they're only reached over the network.
