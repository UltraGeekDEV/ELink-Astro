EVent Wiki

A distributed event and RPC mesh for .NET, with network-wide type agreement (NOTES).

EVent is a .NET 8 library for building a network of cooperating processes (nodes) that talk through named events rather than addresses. Nodes link to each other over interchangeable transports (TCP with UDP multicast discovery, and serial ports today). Every node learns which events the rest of the network is interested in, and routes each message only toward the nodes that want it.

Nodes communicate in two ways:

  • Events: fire-and-forget messages that reach every interested party in the network.
  • dRPC (distributed RPC): a call that goes out to every node that registered a handler for a name, and returns the list of all their answers. It is not a call to one target.

On top of that sits NOTES (No Overhead Type Enforcement System). NOTES makes the whole network agree on one type signature per event, once, when an event is first hooked, so messages themselves carry no type information. It also lets nodes whose classes declare fields in different orders still exchange data correctly. Its wire format and type descriptions are called NON (NOTES Object Notation).

Around that: firewall and namespace nodes decide what crosses between networks and group a network's events under a name (Minecraft.Player.Health) that the outside routes as one entry; NON dynamic objects use any event without writing a class for it; and the scripting node connects applications that were never written for each other with a few lines of C#. C++ programs join as typed leaf nodes of a local C# node.

Quick start

The high-level entry point is TypeSafeEVentNode. The snippet below mirrors the bundled Examples project: two nodes, a typed event, and a network link found by UDP discovery.

QuickStart.cs
using Event.CoreFunctionality;                       // TypeSafeEVentNode
using Event.CoreFunctionality.EVentIDs;              // ConnectionTypes
using EVent.Connections.Models.BaseBinaryConvertibles; // Package
using EVent.Connections.TCP;                          // TCPServer
using System.Net;

// Process 1: listen on TCP 5698 and answer discovery requests for "NodeA"
var nodeA = new TypeSafeEVentNode("NodeA", new TCPServer(IPAddress.Any, 5698, "NodeA"));
nodeA.HookEvent("TestA", (CatDescriptor cat) => Console.WriteLine($"got {cat}"));

// Process 2: own listener on 5699, then find "NodeA" via multicast and link to it
var nodeB = new TypeSafeEVentNode("NodeB", new TCPServer(IPAddress.Any, 5699, "NodeB"));
if (!nodeB.TryEstablishConnection(new Package(ConnectionTypes.TCPDiscovery, "NodeA")))
    Console.WriteLine("could not join NodeA's network");

// Typed events are delivered synchronously: FireEvent returns after every subscriber ran.
// It returns false until NodeB knows the agreed type of "TestA" (learned in the
// background right after connecting, or by hooking the event on NodeB too).
bool sent = nodeB.FireEvent("TestA", new CatDescriptor("Tom", 1, 3, "Attila"));

CatDescriptor is a user type that describes its fields to NOTES. See Defining NOTES types for how to write one.

Maturity

Before you rely on EVent in anything important, read the Issues page. In particular: the topology must be a tree (by design; join networks with TryEstablishConnection, which refuses loops), calls wait at most FunctionCallTimeout (30 s by default) and then return the answers they have, and for many concurrent operations the …Async API is the one to use (Threading). A malformed message from a peer drops only that link, and both sides are told (Faults and re-joining).
