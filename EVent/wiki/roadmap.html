Roadmap

What comes next, and the decisions already taken for it. Nothing here is built yet.

The first uses of EVent are on trusted home networks: lights (WLED) reacting to a game on the home Wi-Fi, a game controller on a serial port that fakes XInput or feeds an EVent input engine, mods for Minecraft and Factorio talking to each other. That sets the priorities below.

Decisions

TopicDecision
TrustLinks stay unauthenticated and unencrypted for now: the first users are on trusted networks. Routers bind to loopback where possible.
LanguagesEvery language other than C# joins as a leaf of a C# router; the embedded side gets its own routers (the ESP-NOW dongles).
Leaf transportsTCP loopback today; shared memory later, behind the same Transport interface; serial for microcontrollers.
Dongle topologyA mesh of ESP-NOW dongles, each a router, with a reliable link layer (see below). Custom hardware with more memory may come later.
Microcontroller leavesShould work without heap memory where possible (an Arduino Uno has 2 KB of RAM).

Serial (needs hardware)

Waits for test boards: two ESP32s, one behind a USB-to-TTL converter and one on its native USB port (the ESP32-S2/S3's USB CDC serial has caused problems before, so both paths are tested).

  • Fix I-09 (links dropped after about 1 s of silence, never re-established), I-16 (250-byte receive buffer), I-22 (every unknown port probed every second).
  • Harness scenarios on real ports: both boards, reconnects, sustained input rates.

Micro leaf (any Arduino board)

A leaf for controllers on any Arduino-supported board, over serial, ideally without heap memory (about 0.5–1 KB of RAM). A leaf with endpoints fixed at compile time only needs a small, predictable part of the protocol:

  • Frames: one fixed receive buffer (128–256 bytes); frames are written straight to the port as they are built, with no send buffer.
  • Interest: the router's ListEvents can be large, so it is parsed as it streams in, keeping one flag per own ID.
  • Types: the micro leaf stores nobody else's types and doesn't answer the NOTES functions. At startup it proposes its own types through the router (TryInitiate, Finalize, Abort), keeping one agreed/refused flag per endpoint; the C# side keeps the full picture.
  • Answers: a FunctionReturn needn't repeat the caller's input (the router reads only the handle and the answers), so the input can be dropped once decoded.
  • Calls: a fixed number of call slots, each writing its answer straight into a struct the caller provides.
  • Signatures are generated at compile time (C++17 constexpr, which avr-gcc handles) or by a small desktop tool from the same struct definitions: to be decided when it is tried with avr-gcc.
  • Limits: endpoints fixed at compile time, values no larger than the buffer, no dynamic types, no listing the network.

It is a byte stream, so it can be built and tested on the desktop (TCP or a pseudo-terminal against the C# harness) before the boards arrive.

Handshake v2: frame size

Add the largest frame a side accepts to LinkHandshake (protocol version 2, minimum still 1). A router then never sends a leaf a frame it can't hold: a call that wouldn't fit is refused on the router's side instead of failing quietly on the device. It also bounds I-52.

ESP leaf

The portable core (non.hpp, dyn.hpp, wire.hpp, notes.hpp: C++17, no exceptions, no I/O, no threads) with a leaf sized for an ESP32: one or two threads, small buffers, poll dispatch. ESP-IDF has std::thread and lwIP sockets, so the desktop leaf may compile there, but it is sized for a desktop (up to 64 handler threads, a 64 KB receive buffer). None of it has been compiled for an ESP yet.

ESP-NOW dongle mesh

A dongle adds wireless EVent to any EVent-capable serial or USB port, and dongles form a mesh. Each dongle is a router between its serial link and its ESP-NOW peers.

LayerWhat it does
Spanning treeEVent links must form a tree (loops break interest routing). The dongles build a spanning tree over the ESP-NOW mesh, like the Spanning Tree Protocol network switches use, and rebuild it when a dongle disappears. EVent links run over tree edges only.
Reliable linkA TCP-like layer per tree edge: fragmentation (ESP-NOW frames are 250 bytes, more on newer ESP-IDF), sequence numbers, acknowledgements, retransmits, duplicate suppression.
Router coreInterest routing, prefix routes, call fan-out and answer merging, the handshake and NOTES participation, in portable C++, reusable on the custom hardware later.

All three can be built and tested in simulation first: UDP in place of ESP-NOW, with injected loss, reordering and dongles disappearing.

Other languages and engines

TargetPlan
Java (Minecraft mods)A leaf like the C++ one: sockets and threads, types from Java records or annotated classes. Minecraft's Java 17/21 is fine.
Lua (Factorio)Factorio mods can't open sockets and can't push anything out: the only way in is RCON. So a Lua mod queues outgoing events and exposes a remote interface, and a bridge (a C# leaf) talks RCON to the game: it turns incoming events into remote.call commands and polls the mod's queue every few ticks for outgoing ones. Latency is about one poll interval.
UnityUnity's C# is .NET Standard 2.1, which can't load a .NET 8 library. Preferred: multi-target the C# core to .NET Standard 2.1 (polyfills for Int128, generic math, Random.Shared and similar), so Unity gets the full node. Alternative: a small .NET Standard 2.1 leaf.
Godot 4 (C#), plain .NET, UnrealWork today: the C# library, or the C++ leaf.

Leaf conformance kit

The harness drives the C++ leaf through evn_leaf_peer, a small command-line peer (commands on stdin, replies on stdout, values as hex of their NON bytes). Made the standard, every new leaf implements the same peer tool and reuses all Y scenarios unchanged: the cheapest way to verify Java, Unity and Lua leaves.

Smaller items

  • Build and run the C++ leaf on Windows (the Winsock transport is written, never compiled).
  • Game input at 500–1000 Hz: use PublishEvent (fire and forget: no acknowledgements, ordered; several times the throughput of FireEvent) or raw events; add a latency and throughput scenario over serial.
  • A WLED bridge example: a C# node (or a scripting-node script) turning events into WLED's JSON API or UDP real-time protocols (DDP, E1.31). A native EVent usermod inside WLED needs the ESP leaf first.
  • The shared-memory transport for local leaves.
  • Authentication and encryption, when EVent leaves trusted networks.

Suggested order

  1. Leaf conformance kit.
  2. Micro leaf and handshake v2 (desktop-tested).
  3. Java leaf.
  4. Unity (multi-target).
  5. Factorio mod and bridge.
  6. Router core and the reliable mesh layer, in simulation.
  7. With the boards: Serial fixes, the micro leaf on real boards, ESP-NOW for real.
