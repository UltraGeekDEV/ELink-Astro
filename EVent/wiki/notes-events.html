NOTES events reference

API reference for the system events (dRPC functions) NOTES uses to coordinate the network.

NOTES coordinates entirely through dRPC functions that every TypeSafeEVentNode registers on its local client in its constructor TypeSafeEVentNode.cs:59–68. Their IDs are constants in Event.CoreFunctionality.EVentIDs.NOTESEvents EVentIDs.cs:28–50. Because they're ordinary functions, calling one means asking every NOTES node in the network, and you get a list with one answer per node.

Descriptor negotiation

TryInitiateNOTESDescriptor : NOTESEventDescriptor -> BinaryConvertibleInt32

Phase 1 of the agreement: “I'd like to establish this signature for this ID.” Each responder answers:

AnswerMeaningProposer reaction
2 EstablishedAn equal descriptor is already established here.Abort, fetch it with QueryDescriptors, adopt it, and take the already-established path.
1 PendingAn equal competing proposal with a higher weight is pending.Abort, then retry after 100 ms (unless someone also said -1).
0 AcceptedAccepted. The responder now holds the proposal as pending, until the TTL expires.If everyone says 0, go to Finalize.
-1 ConflictA different descriptor is established, or pending and not expired, for this ID.Abort, then return false.

The values are constants in Event.CoreFunctionality.EVentIDs.NOTESInitiateReplies. Handler: TypeSafeEVentNode.cs. See the responder table.

FinalizeNOTESDescriptor : NOTESEventDescriptor (the full proposal) -> BinaryConvertibleInt32

Phase 2: commit exactly this proposal as established and drop any other pending proposal for its event. Answers 1 if committed, or if an identical descriptor is already established, and -1 if a different type is already established. It doesn't depend on the node still holding the pending entry, so a TTL expiry can't break it. On any -1 the proposer aborts and returns false. Handler: TypeSafeEVentNode.cs.

Note

Before commit 7e35633, Finalize carried only the event ID, so each node committed whatever proposal it happened to hold.

AbortNOTESDescriptor : NOTESEventDescriptor (the proposal to withdraw) -> NOTESVoid

Withdraws a proposal after it wasn't accepted everywhere, or after Finalize found a conflict. Each node removes its pending entry for the event only if it's literally this proposal: the same type and the same random weight (NOTESEventDescriptor.IsSameProposal). A competitor's pending proposal is never touched. Established descriptors are never affected. Handler: TypeSafeEVentNode.cs.

QueryDescriptors : BinaryConvertibleString (event ID) -> NOTESEventDescriptor

Returns the established descriptor for the ID. A node that doesn't know the ID returns null, which the function layer drops, so it contributes no answer (before commit 56bab8b it answered with a placeholder whose EventID was the string "null", which a merge could adopt as a real event). HookEvent uses it when an equal descriptor turns out to be established already. Merges and link-ups use the batched NOTESQueryDescriptorSet and NOTESShareDescriptors instead. Handler: TypeSafeEVentNode.cs:204–216.

// From any EVentNode that is part of the network (see the cookbook for joining one):
var answers = node.CallFunction<NOTESEventDescriptor, BinaryConvertibleString>(
                  NOTESEvents.QueryDescriptors, "TestA");
foreach (var d in answers)   // empty if no node knows "TestA"
    Console.WriteLine(string.Join(", ", d.Expected.binaryConvertibles.Select(s => s!.Text)));
NOTESQueryDescriptorSet : BinaryConvertibleCollection<BinaryConvertibleString> (event IDs) -> BinaryConvertibleCollection<NOTESEventDescriptor>

The batched form of QueryDescriptors: every node answers with the descriptors it has established for any of the IDs, or not at all if it knows none. A merge calls it once, through the probe, with every ID established on the merging side, and refuses on any conflict. Its presence in a peer's ListEvents is how the merge probe decides that the peer runs NOTES. Handler: TypeSafeEVentNode.cs:219–233.

NOTESShareDescriptors : BinaryConvertibleCollection<NOTESEventDescriptor> -> BinaryConvertibleCollection<BinaryConvertibleString>

“Here is every descriptor I know.” Each node applies FinalizeNOTESDescriptor's rule to each one (commit if absent, and drop any other pending proposal for it) and answers with the IDs for which a different type is established, or not at all if there are none. Both endpoints of a new link call it once, network-wide, from OnConnected. It replaces the per-ID QueryDescriptors and per-descriptor FinalizeNOTESDescriptor calls OnConnected used to make, and OverrideDescriptor, which a merge used to call once per descriptor and which let any node overwrite an agreed type (removed in commit e5b2492). Handler: TypeSafeEVentNode.cs:234–245.

Flow control

StopEvents : NOTESVoid -> NOTESVoid

Closes this node's execution gate and answers once in-flight HookEvent/FireEvent calls have left it. New ones wait at the gate. Sent to the merging group (never the target's network) once the loop check has passed. The handler is asynchronous: nothing waits on a thread for the drain (before commit 2c9a853 it blocked a link reader and could deadlock). Handler: TypeSafeEVentNode.cs:289–294.

AllowEvents : NOTESVoid -> NOTESVoid

Re-opens the gate. Sent to the merging group in the finally of TryEstablishConnection. Handler: TypeSafeEVentNode.cs:295–299.

AwaitReady : NOTESVoid -> NOTESVoid

Enters and immediately leaves the gate, so it answers only when the gate is open. Callers poll it until the returned list is non-empty. That shows the NOTES functions are reachable, and on the local node it confirms that the local client's registrations have been routed. Handler: TypeSafeEVentNode.cs:87–92.

Merges in flight

NOTESMergePing : BinaryConvertibleUInt64 (merge number) -> BinaryConvertibleCollection<BinaryConvertibleUInt64>

“Which merges are you running?” Each typed node answers with the numbers of its own merges in flight, other than the pinging one, or not at all if it has none; a merge probe answers with its owner's number. It records nothing and queries nothing. The merging node calls it once per round, on its own network only; the probe subscribes to it at the target, which is how a ping that comes back through the target is recognised (our own number in the answers). See Loop prevention. Handler: TypeSafeEVentNode.cs:523–530. (Until commit 8c7a5cf every node kept expiring records of every number it heard, refreshed by a beacon, and a second function, NOTESMergeEnd, cleared them.)

Unused

HandleEvent

Declared in NOTESEvents but never registered or called (I-29). It may be a leftover from before typed events were implemented as functions under their own ID.

User typed events

<eventID> : T (FlexibleSerDes-encoded) -> NOTESVoid

Every TypeSafeEVentNode.HookEvent<T>(id, cb) registers a function under id whose input is decoded with the event's NOTESFlexibleSerDes and whose output is NOTESVoid.Void (one 0x00 byte). FireEvent calls it. The list of NOTESVoid answers (one per subscriber) is discarded. A typed function (RegisterFunction<TIn, TOut>) is the same thing with a real return type, and CallFunction<TIn, TOut> keeps the answers. See How EVent and NOTES fit.
