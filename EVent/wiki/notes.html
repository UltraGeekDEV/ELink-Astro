What is NOTES?

No Overhead Type Enforcement System: the network agrees on each event's type once, so messages don't have to carry it.

NOTES stands for No Overhead Type Enforcement System. Its wire format and type descriptions (the canonical signature, the byte layout it defines, and the JSON that describes it) are called NON, NOTES Object Notation; NON dynamic objects use them to work with any event without a C# class. It is the layer that gives EVent typed events and typed functions (typed dRPC). The public face is TypeSafeEVentNode; the machinery lives in NOTESDescriptor, NOTESEventDescriptor and NOTESFlexibleSerDes.

The problem it solves

At the EVent level, an event is a string ID plus opaque bytes. Sender and receiver each pick a C# type and hope the layouts match:

// node 1
local.FireEvent("Temperature", new Reading { Celsius = 21.5f, SensorId = 7 });
// node 2, written by someone else, months later
local.HookEvent("Temperature", (OtherReading r) => ...);   // different field order? different types?

If the layouts differ, the receiver gets garbage values or a parse failure, which the raw layer drops silently. In a network built from independently deployed programs (and, per the project goals, different platforms and languages), nothing keeps them aligned.

The usual fixes are self-describing formats (JSON, or protobuf with field tags) or a shared schema compiler. Both cost something on every message: names or tags on the wire, or a build step and a shared artifact.

The idea

  1. Types describe themselves. Each composite type registers its fields (name, type, accessor) in a static NOTESDescriptor. No reflection is used.
  2. The description becomes a signature: a small type graph, with one =Root entry naming the event's type and one Name{field:Type,...} definition per record type. Collections (Cat[]) and recursive types are part of it.
  3. The network agrees once per event. The first node to hook an event proposes its signature. A two-phase, network-wide dRPC exchange either establishes it everywhere or reports a conflict. After that the signature is fixed for the event. A typed function is agreed the same way, as a pair: its input signature and its return signature. An event is a function that returns Void.
  4. The signature is canonical. The fields inside each definition, and the definitions themselves, are sorted ordinally. The agreed layout depends only on the structure, never on who hooked first or how a class was declared.
  5. Everyone serializes in the agreed order. Each node builds a NOTESFlexibleSerDes that writes its own class in the canonical layout: a record as its fields in sorted order, a collection as a count plus its elements, a leaf as its own bytes. Classes with the same fields in a different declaration order therefore produce identical bytes.
  6. Messages carry only values. No names, tags or type IDs go on the wire. The event ID implies the layout. This is the no overhead part.
  7. Merges check first. Before two networks are linked, TryEstablishConnection makes sure (with one ping of its own group) that the link wouldn't close a loop and no conflicting merge is in flight, then compares descriptors; a conflicting event makes it refuse.

What “no overhead” does and doesn't mean

CostNOTES
Bytes per messageOnly values. The payload is the leaf values in canonical order; a collection adds its 4-byte element count. For a kennel of 10 cats that's 352 bytes against 536 for the same data as JSON (harness U10).
Schema compiler / generated codeNone. Types register fields by hand in a static constructor.
ReflectionNone. Accessors are plain lambdas.
Per-event set-upOne or two network-wide dRPC rounds on the first HookEvent of an event, with 100 ms back-off retries on contention.
Per-message deliveryTyped events are sent as dRPC calls, so every FireEvent waits for every subscriber to acknowledge with a NOTESVoid. That's a latency and round-trip cost that raw events don't have. See How EVent and NOTES fit.
Merging networksOne merge ping over the joining group, then typed traffic in the joining group pauses for one descriptor query and the link handshake. The target network is never paused.

What counts as “the same type”

Two C# types are compatible for an event if their signatures are identical. That compares:

  • every record type's Name property ("Cat"), not its C# class name;
  • each record's registration names ("Extra data"), not its C# property names, and the type registered under each;
  • leaf types by their Name ("string", "UInt64", …);
  • collections by element type and cap: Cat[], Cat[<=16] and Cat[][] are three different types;
  • whether a field is optional: Next:Node? and Next:Node differ.

Declaration order, namespaces and C# property names don't count (I-33). Within one event a name means one structure: two C# types that share a record Name must define it identically, or NOTES refuses the type.

Where it's enforced

On every path. A node proposing a new type gets false from HookEvent if another type is agreed or pending. A node joining an already-agreed event compares its local signature with the agreed one, and HookEvent / FireEvent return false on any difference, whether a missing field, an extra field or another field type (commit c0a0c42). Leaf types such as int32, string or NOTESVoid used directly as an event's type are their own single field (signature ["=int32"]), so they're checked and their value is sent. Before that commit, their signature was empty: any two leaf types counted as equal, and nothing was transmitted. The checks reach inside collections too (commit 729bbe2): a collection whose element type differs, even only by an extra field, doesn't match.
