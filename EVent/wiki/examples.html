Examples & cookbook

A walkthrough of the bundled demo, plus snippets you can adapt.

The bundled Examples project

Examples/ is a console app that starts three TypeSafeEVentNodes in one process (Program.cs) and chains them together over TCP on localhost, using UDP discovery:

NodeFileListensDoes
NodeANodeA.csTCP 5698, discoverable as "NodeA"Hooks TestA as CatDescriptor and TestB as NOTESTEstObject. For every console line it fires both, printing the received values and TestB's signature.
NodeBNodeB.csTCP 5699, "NodeB"Joins NodeA's network. Acts as a pure relay.
NodeCNodeC.csTCP 5700, "NodeC"Joins NodeB, then hooks TestA as <strong>CatDescriptorReordered</strong>, the same fields declared in a different order. This demonstrates NOTES reordering.
HubDNodeB.cs:27–36–Commented out. It shows the older FireEvent(AdminEvents.CreateInterconnect, …) way of linking.

What happens, in order

  1. All three constructors run in parallel. Each starts its TCP listener and discovery responder, registers the NOTES functions, and waits for AwaitReady.
  2. NodeA hooks TestA. Its network is just itself, so the agreement trivially succeeds, and the signature [=Cat, Cat{Age:UInt64,ID:UInt64,Name:string,Owner:string}] is established. The same happens for TestB.
  3. NodeB calls TryEstablishConnection(TCPAUTO "NodeA"): stop events, discover NodeA over multicast, probe, confirm NodeA runs NOTES, compare descriptors (NodeB has none), close the probe, dial for real. The link handshake runs, and NodeB's OnConnected imports TestA and TestB.
  4. NodeC does the same toward NodeB. Its OnConnected imports the descriptors in the background and re-shares them with the whole network.
  5. NodeC hooks TestA with CatDescriptorReordered. If the import has finished, it takes the established path and reorders its SerDes to the canonical order. If not, NodeA and NodeB answer Established to its proposal, and C adopts their descriptor straight away.
  6. Type a line into the console: NodeA fires TestA (a CatDescriptor named after your input) and TestB. NodeA's own handler prints, NodeC's handler prints the reordered cat, and each FireEvent returns after both handlers have run.
Note

Because the whole demo runs in one process, it doesn't exercise cross-process issues. NodeC's message text is also misleading: it says the data came “from HubC”, but it originates at NodeA (I-36).

Running it

dotnet run --project Examples
# type any text + Enter; watch NodeA and NodeC print the cat

Multicast discovery needs a network interface that can join the multicast group, and a firewall that allows UDP 8563 and the TCP ports.

Cookbook

Snippets built from the public API as it exists in the code. They have not been compiled, because no .NET SDK was available while writing this wiki, but they follow the signatures exactly. Each one notes any caveats.

1. A typed message type

SensorReading.cs
using Event.Connections.Models.BaseBinaryConvertibles;
using EVent.Connections.Models.BaseBinaryConvertibles;

public class SensorReading : IBinaryConvertible
{
    public BinaryConvertibleString Sensor  { get; set; } = "";
    public BinaryConvertibleFloat  Celsius { get; set; } = 0f;
    public BinaryConvertibleUInt64 Ticks   { get; set; } = 0UL;

    public override string Name => "SensorReading";               // part of the contract!
    private static readonly NOTESDescriptor descriptor = new NOTESDescriptor();
    public override NOTESDescriptor Descriptor => descriptor;
    static SensorReading()
    {
        descriptor.RegisterField("Sensor",  (SensorReading x) => x.Sensor);
        descriptor.RegisterField("Celsius", (SensorReading x) => x.Celsius);
        descriptor.RegisterField("Ticks",   (SensorReading x) => x.Ticks);
    }
    public override bool FromBytes(ref Span<byte> d) => descriptor.FromBytes(this, ref d);
    public override byte[] ToBytes() => descriptor.ToBytes(this).ToArray();
    public override string ToString() => descriptor.ToString(this);
}

2. Typed pub/sub across two processes

Typed pub/sub
// ---- process "Collector"
var collector = new TypeSafeEVentNode("Collector", new TCPServer(IPAddress.Any, 7000, "Collector"));
await collector.HookEventAsync("sensors/reading", async (SensorReading r) =>
{
    // A thread-pool task per delivery; the prober's FireEventAsync completes when this does.
    // It may await other calls, including FireEventAsync back to the prober.
    await StoreAsync(r);
});
Console.ReadLine();

// ---- process "Probe-7"
var probe = new TypeSafeEVentNode("Probe-7", new TCPServer(IPAddress.Any, 7001, "Probe-7"));
if (await probe.TryEstablishConnectionAsync(new Package(ConnectionTypes.TCPDiscovery, "Collector")) != MergeResult.Connected)
    return;
// FireEventAsync returns false until Probe-7 has learnt the agreed type (shared right after
// connecting). Hooking the event also works, but makes Probe-7 a subscriber.
while (!await probe.FireEventAsync("sensors/reading", new SensorReading { Sensor = "probe-7", Celsius = 21.5f }))
    await Task.Delay(50);

3. Linking by address instead of discovery

Direct TCP
var node = new TypeSafeEVentNode("Edge", new TCPServer(IPAddress.Any, 7101));
var target = new TCPConnectionData
{
    TargetIP   = "10.0.0.5",
    TargetPort = 7000,
};
node.TryEstablishConnection(new Package(ConnectionTypes.TCP, target));
// or: new TCPConnectionData(new IPEndPoint(IPAddress.Parse("10.0.0.5"), 7000))
Note

SourcePort (default 0) picks which of the node's TCP servers dials: the one listening on that port. Leave it 0 when the node has one.

4. Raw events with a plain EVentNode

Raw events
using EVent.CoreFunctionality;                          // EVentNode
using Event.CoreFunctionality;                          // LocalCallbackClient
using EVent.Connections.Models.BaseBinaryConvertibles;  // primitives
using EVent.Connections.TCP;

var node = new EVentNode("Telemetry", new TCPServer(IPAddress.Any, 7200, "Telemetry"));
node.Run();
var local = node.AddLocalCallbackLayer();

Action<BinaryConvertibleFloat> onTemp = t => Console.WriteLine($"{t.value:0.0} °C");
local.HookEvent("temp", onTemp);                        // announces interest network-wide
local.FireEvent("temp", (BinaryConvertibleFloat)21.5f); // explicit cast: inference won't convert
local.UnHookEvent("temp", onTemp);                      // same delegate instance
Note

Raw events aren't type-checked. The receiver's FromBytes decides, and failures are dropped silently. Don't use the same ID as a typed event or a function: calls to it would get no answer from the raw subscriber.

5. Plain dRPC: ask every node

Scatter/gather query
// on every node that should answer
local.RegisterFunction<NOTESVoid, BinaryConvertibleString>("whoami", _ => Environment.MachineName);

// anywhere
foreach (var name in node.CallFunction<BinaryConvertibleString, NOTESVoid>("whoami", NOTESVoid.Void))
    Console.WriteLine(name.Text);

Connecting a plain EVentNode

EVentNode has no connect method. Inject a CreateInterconnect admin package through a local layer, which is exactly what TypeSafeEVentNode does internally TypeSafeEVentNode.cs:294, TypeSafeEVentNode.cs:306:

Linking a raw node
using Event.CoreFunctionality.EVentIDs;
using EVent.Connections;

var connected = new ManualResetEventSlim();
node.OnConnected(_ => connected.Set());

var connectionInfo = new Package(ConnectionTypes.TCPDiscovery, "Collector");
local.SendPackage(new Package(AdminEvents.CreateInterconnect, PackageType.ServerAdminEvent, connectionInfo));

connected.Wait(TimeSpan.FromSeconds(10));
Caution

This skips the NOTES compatibility check, which is fine for tools. Discovery that finds nobody gives up after ClientTCPDiscovery.Timeout (10 s by default), and the dial fails without holding up the node's local layer.

6. A network monitor

Monitor
var monitor = new EVentNode("Monitor", new TCPServer(IPAddress.Any, 7300));
monitor.Run();
var local = monitor.AddLocalCallbackLayer();
monitor.OnEventAdded(id   => Console.WriteLine($"+ {id}"));
monitor.OnEventRemoved(id => Console.WriteLine($"- {id}"));
monitor.OnDataReceived((p, _) => Console.WriteLine($"  {p.type} {p.EventID} ({p.Data.Length} B)"));
// link as in "Connecting a plain EVentNode", then e.g. dump the agreed type of an event:
foreach (var d in monitor.CallFunction<NOTESEventDescriptor, BinaryConvertibleString>(NOTESEvents.QueryDescriptors, "TestA"))
    Console.WriteLine($"{d.EventID.Text}: {string.Join(", ", d.Expected.binaryConvertibles.Select(s => s!.Text))}");
Note

OnDataReceived only sees traffic that is routed through the monitor, meaning events it (or something behind it) is interested in. In a tree, that's the traffic on the monitor's own branches.

7. Serial device checklist

  • Implement Package framing on the device.
  • At 9600 baud, echo SerialHandshake with the host's server ID, then answer SetBaudrate with an int32 and switch rates.
  • Answer InterconnectRunning with your ListEvents, answer QueryEvents with ListEvents, and send EventAdded for what you provide.
  • Send something at least every second, or the host drops you (I-09). Keep packages under 247 bytes (I-16).
  • To receive typed events, register the event ID and answer each FunctionCall with a FunctionReturn whose ReturnValues contains one package with data 0x00 (a NOTESVoid), restoring the caller's handle. Decode the parameters in the event's established field order.

Pitfalls

SymptomLikely cause
FireEvent takes exactly the call timeout (30 s by default)A subscriber's callback is stuck; FireEvent stops waiting for it after FunctionCallTimeout or the timeout you pass.
Everything slows down under loadMany thread-pool threads blocked in FireEvent / CallFunction. Use the …Async forms (Threading).
HookEvent takes long to returnA merge is in progress (typed operations are paused until it ends, which each merge step bounds with MergeStepTimeout), or a node doesn't answer the agreement calls (bounded by FunctionCallTimeout).
TryEstablishConnection returns UnreachableDiscovery found nobody, or the target didn't answer within MergeStepTimeout.
FireEvent returns falseThe type isn't agreed yet, or this node hasn't learned it.
HookEvent returns falseAnother type is established for the ID, or a proposal of another type is pending. A pending one expires after ProposalTimeToLive (5 s by default), so retrying later can succeed.
HookEvent / FireEvent return false on a node that knows the eventYour type's signature differs from the agreed one: a missing or extra field, another field type, or another root Name.
Serial device disconnects after a secondI-09
CPU at 100% (or more) running the ExamplesBusy while(true){} loops (I-36).
Traffic storm after adding a linkYou closed a cycle with a raw link. That's expected: the core doesn't stop loops (Topology rules). Join through TryEstablishConnection, which refuses such links.
TryEstablishConnection returns falseUse TryEstablishConnectionAsync (or the out MergeResult overload) to see why. AlreadyConnected: the target is already in your network. Timeout: a node on the way stopped answering. Busy: a merge in the way never ended, so its node is broken.
